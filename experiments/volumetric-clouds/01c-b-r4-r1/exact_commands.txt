2. Terminal / interactive matrix (58 cases)
   powershell -NoProfile -ExecutionPolicy Bypass -File run_01c_b_r4_faults.ps1
   python parse_01c_b_r4_faults.py

   Every case is a separate child process under OGSRCloudsTerminalHarness with a
   hard timeout. The harness creates:
     - a shared-memory witness (atomic events, submit/fence counters and the
       interactive diagnostics counters), and
     - an ALWAYS-created pipe-status block (independent of the witness), which
       records per stream whether SetStdHandle / _open_osfhandle / _dup2
       succeeded, whether activation happened, the probe target and whether the
       pipes were later deactivated.
   A child killed by the timeout is counted as FAIL; the only exceptions are the
   explicitly marked positive controls (control_blocked_pipe_probe,
   control_stdout_probe, control_stderr_probe, control_both_stdout_probe,
   control_both_stderr_probe), which MUST time out.

   New in R4-R1:
     control_stdout_probe          stdout filled, probe writes to stdout
     control_stderr_probe          stderr filled, probe writes to stderr
     control_both_stdout_probe     both filled, probe writes to stdout
     control_both_stderr_probe     both filled, probe writes to stderr
     pipe_setup_failure_no_activation
                                   harness passes an invalid handle on purpose;
                                   installation must FAIL, must not report
                                   activation, and the child must keep running
     inflight_no_block             interactive multi-frame diagnostics, no pipes
     inflight_blocked_stdout       same with a full stdout
     inflight_blocked_stderr       same with a full stderr
     inflight_blocked_both         same with both full
