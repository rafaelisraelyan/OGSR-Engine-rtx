## 6. Performance source assessment — needs uncapped repeat A/B

Supplied harness source samples **`Device.fTimeDelta * 1000`** (frame delta, including frame pacing), stores up to 100,000 samples, sorts and picks `floor(p*(n-1))`. The ZIP provides **only aggregate `g51-stats-*.txt`**, not raw per-frame data, so reviewer **cannot recompute p50/p95/p99 independently**. Verified internal consistency of reported summaries:

| Test | Frames | Mean ms | p50 ms | p95 ms | p99 ms |
|---|---:|---:|---:|---:|---:|
| S1 ODE | 3600 | 33.349 | 33.3324 | 33.3681 | 33.4318 |
| S1 PhysX | 3600 | 33.4946 | 33.3322 | 33.3646 | 33.4734 |
| S2 ODE | 3600 | 33.3488 | 33.3320 | 33.3668 | 33.4027 |
| S2 PhysX | **3900** | 33.7462 | 33.3324 | 33.3675 | **39.9911** |
| S2 mixed | 3600 | 33.7775 | 33.3321 | 33.3751 | 39.9938 |

S2 p99 reported increase **+6.5884 ms (+19.7% in p99 frame duration)** vs ODE; mean **+0.3974 ms**, but this is not an isolated CPU PhysX cost: tests use ~30 FPS frame cap/pacing, differing 3600/3900 frame windows, and no per-frame sample trace or CPU physics-step timing A/B. **Do not assert S2 p99 is acceptable, unacceptable, or caused entirely by PhysX** from this data. Investigate with equal-length, controlled, **uncapped** frame samples, 3+ repeated runs per mode, p50/p95/p99, physics CPU step, number of active ragdolls and capture cost. Keep source S1/S2 functional success separate.
