# OGSR PhysX — G5.1-S3R: Direct 16-Human Real-Gameplay Validation

**Decision:** 2026-11-11 (project owner + Tech Lead). **Status: TASK AUTHORIZED / NOT RUN / NOT ACCEPTED.**

**Supersedes the testing sequence** from [S3 four-ragdoll task](p3.3g5.1-s3-four-human-ragdolls.md) and the S3→S4→S5 step-by-step *approval gates* in [human rollout matrix](p3.3g5.1-human-npc-ragdoll-stress.md). The previous documents and accepted S1/S2/S2R2 results remain part of the audit trail; this is not a retroactive S3/S4/S5 PASS.

## Rationale and scope

Historical P3.3 in-game diagnostic smoke already *reported* 4/8/32/40 concurrent PhysX ragdolls and capacity fallback (32: 55 dropped physics steps; 40: 57). The raw 32/40 logs were not independently replayed and that experiment did not prove postmerge model diversity, ownership, collision, loot, lifecycle and real-performance correctness. See [historical stress evidence index](p3.3-historical-all-human-32-40-smoke.md). Repeating individual 4→8→16 *acceptance submissions* adds overhead without addressing those missing guarantees.

**New execution model:** one controlled 16-concurrent-real-human-NPC test campaign on the merged `prypiat` source, with in-run 4 and 8 checkpoints **for observability and early stop only**, **not separate independent-review/authorization gates**. The owner explicitly authorizes **controlled testing up to 16**. This does **not** authorize code merge, production default-on, 32/40 retesting, mutants, PhysX locomotion or changed ODE fallback.

## Single campaign: matched 16-human A/B and rig coverage

- Same machine, level, save, camera, renderer, weather, graphics settings, scripted NPC mix and capture windows. Drive **the same 16 real `CAI_Stalker` NPC death transitions** with ODE feature-off and PhysX feature-on in separate matched runs. Synthetic PhysX actors cannot count toward the 16.
- In PhysX mode verify 16 unique NPC IDs **simultaneously PhysX-owned for a meaningful measured interval**, not 16 sequential spawns, ODE-owned fallbacks or stale counts. Capture checkpoints at 4, 8 and 16, but no per-checkpoint acceptance package. If any checkpoint has a crash, UAF, incorrect ownership, nonfinite skeleton or obvious bad collision, stop and file exact failing checkpoint; never proceed blindly.
- **Model diversity is central:** at least two distinct **runtime visual paths successfully PhysX-captured**, not just NPC sections or outfit names; aim across as many different H0 humanoid visual/rig families as available in one reproducible level. Explicitly include `actors\\stalker_merc\\stalker_merc_2` and `actors\\stalker_merc\\stalker_merc_4` if available; a loaded NPC visual alone does not establish a PhysX rig PASS. Record every NPC ID, section, actual visual path, visual/rig family, eligibility and fallback code, bone count, actual rigid bodies/shapes/joints, transform finiteness, continuity, animation-to-physics pose/velocity handoff and skin correspondence.
- Assert **one authoritative dynamic solver per NPC**: PhysX ownership and no active ODE shell for each captured ragdoll; otherwise a reason-coded ODE fallback with no ghost PhysX instance. Confirm stable terrain/world static collisions, no falling through world, loot/corpse/inventory interactions, no spurious impulses or disappearing visuals. Check mixed visual families in the same session, not only separate runs.
- At max capacity verify an eligible **17th NPC** safely uses ODE fallback and that capacity reuse returns a freed slot to PhysX when possible. Negative real static-tile coverage test should be attempted with `-physx_static_tiles`, log reason-coded fallback; mark NOT RUN if no valid negative case is reproducible.
- At **16 simultaneously active before each disconnect**, execute at least two same-process `disconnect → teardown → new-level ready` transitions and normal OS exit 0; repeat in separate process. Prove `V2LiveCount=0` after teardown, callbacks unregistered, DLL `lease_refs=0`, no stale generation/owner, and new level creates correct instances.
- Save/load test while PhysX ragdolls exist. **Rigid PhysX states are not serialized**; legacy ODE corpse restoration is the expected documented behavior, not a requirement to reconstruct the exact PhysX pose from save.

## Performance: separate CPU and frame pacing

- Minimum **three matched independent ODE runs and three PhysX runs** from the same source pin, scene/save and equivalent 16-NPC events. Capture raw frame ID, timestamps, frame wall dt, ODE physics CPU step, PhysX SceneStep CPU and wall, live PhysX/ODE counts, spawn/capture/teardown markers, memory commit/working-set/peak and threads/CPU utilization where feasible.
- Calculate p50/p95/p99, mean, max and sample counts per capture window and per 4/8/16 checkpoint; count >5ms physics steps, >50ms frames and dropped physics ticks. Include calculation script and per-NPC visual coverage summary.
- Explain/measure 30-FPS pacing seen in S2R2 despite `nofpslock` (vsync, engine pacing, test harness, or other *verified* cause); if unresolvable, mark uncapped comparison **NOT VERIFIED**. Distinguish instrumented WPO/LTCG-off from true optimized Release; do not claim production budget with different build flags.
- Compare ODE and PhysX with equal workload, but avoid claiming identical internal physical behavior (different solvers). Report regression trends and measured overhead honestly.
