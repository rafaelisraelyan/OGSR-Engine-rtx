# P2.1 - First Real NPC PhysX Ragdoll

**Status: PASS.** One real Zaton stalker was transitioned from animation to a
PhysX CPU ragdoll: 11 bodies, 10 joints, 47 mapped bones, a 3,136-triangle level
fragment, a 0.00012 m first-frame bone error and 47 active bone callbacks. The
ragdoll is visibly rendered on the level ground in the captured screenshots.
Simulation, collision, impulse, pause and time-factor paths work. The smoke
harness moves the live NPC 3 m in front of the actor and stops the archive
loading screen so the camera can see it; the capture, PhysX transition, physics
and bone publication are the normal runtime path.

No other NPC, no ODE replacement, no save/load and no DX12/DXR work is included.
The P2.2A mass/stability follow-up is documented in
`docs/p2.2a-physx-ragdoll-stability.md`.

## Feature flags

| Flag | Default | Meaning |
|---|---|---|

| `-physx_ragdoll <name-or-section>` | off | Explicit permission for one NPC; ODE remains the default |
| `-physx_ragdoll_smoke` | off | Diagnostic: stage the camera/target, send a lethal hit, pause/time-factor checks |
| `-physx_ragdoll_force_free` | off | Diagnostic: ignore a death animation and force the free-ragdoll branch (implied by smoke) |

A normal build with no flags behaves exactly as before: ODE death, no PhysX DLL
load, no `OGSR_PHYSX_RAGDOLL` symbols.

## Architecture

- `ogsr_physx_runtime.dll` now exports both the P2.0 test context and a
  level-scoped NPC ragdoll runtime. The ragdoll API is plain C/POD in
  `physics_physx/physx_ragdoll_c.h`; no STL or PhysX type crosses the DLL.
- One `PhysXRagdollWorld` (one `PxScene`, foundation, dispatcher and materials)
  per level, not per NPC or per bone. A second activation is rejected and falls
  back to ODE. `OgsrPhysXRagdollRuntimeDestroyInstance` reuses the same handle.
- The game builds `RagdollDescription`/`RagdollInitialState` in memory from
  `PhysicsAdapterOGSR` (`captureFromOgsr`). No JSON file is required at runtime.
- Static collision is a 48 x 24 x 48 m `CObjectSpace::BoxQuery` fragment around
  the NPC, capped at 8,192 triangles and uploaded before `create()`. The test
  fragment contained 3,135 triangles. Bounds and triangle counts are logged.
- The PhysX scene is stepped once per level frame in `CLevel::OnFrame` before
  `Objects.Update`; no render callback touches `PxScene`.

## Transition and ownership

`CCharacterPhysicsSupport` now has an explicit `ownerNone / ownerODE /
ownerPhysX` state.

- `KillHit` selects the death motion first. A valid special death animation
  stays on ODE. Only the free-ragdoll branch asks the PhysX runtime.
- `in_Die` (script kill without a hit) also tries the free PhysX ragdoll.
- Capture uses a temporary, inactive `preBuild_FromKinematics`/`Build` ODE
  shell, then destroys it. It never runs that shell and never creates a second
  active ODE shell.
- Capture, static-fragment upload or PhysX creation failure returns `false`
  before any game state is committed; the original ODE `CreateShell` path then
  runs unchanged.
- On success the movement controller is destroyed, IK/animation movement is
  stopped, and `m_pPhysicsShell` stays null. `m_owner = ownerPhysX` prevents a
  second `KillHit`, `ActivateShell` or ODE shell from taking ownership.
- `SetRemoved`, `in_NetDestroy`, `in_ChangeVisual` and the destructor release
  the PhysX state and reset the bone callbacks. Level unload destroys the
  runtime world first; character destructors only reset local state.
- One diagnostic exception: OGSR's capture marks a zero-mass/shapeless root as
  `StaticRoot`, which would anchor the ragdoll in the air. The runtime promotes
  that root to a 0.5 kg dynamic body (keeping its shapes, adding a small sphere
  only if it has none). This is a documented P2.1 approximation.

## Bone readback

- Each visible bone gets a `bctCustom` overwrite callback. The callback writes
  a model-space `Fmatrix` from a published snapshot; it never reads PxScene.
- Body bones use `inverse(entityWorld) * bodyWorld`. Merged bones use
  `inverse(entityWorld) * (parentBodyWorld * mergedLocal)`. Skipped bones keep
  the frozen animation pose.
- `CCharacterPhysicsSupport::UpdatePhysXRagdoll` sets `mXFORM` from
  `pose.entityWorld`, updates the snapshot, then `CalculateBones_Invalidate` +
  `CalculateBones(TRUE)`.
- First-frame continuity against the last animation pose: **0.00007-0.00021 m**
  across runs. Active callback count: **47**.

## Repeated activation and lifecycle

- `OgsrPhysXRagdollRuntimeHasInstance()` rejects a second active ragdoll; a
  second NPC falls back to ODE rather than creating a second scene.
- The C ABI test destroys and recreates a ragdoll on the same runtime and checks
  that the old bodies are gone (`physics_physx_ragdoll_abi_tests`).
- `SetRemoved`, `in_NetDestroy`, `in_ChangeVisual` and the character destructor
  release the state and reset callbacks. The level unload path was exercised in
  P2.0 and is unchanged; P2.1 adds the world destruction to the same hook.
- An explicit in-game NPC-deletion/rebuild test was not run; this is listed as
  a limitation rather than claimed as PASS.

## Known limitations

- **Visibility needs diagnostic staging in this archive runtime.** The smoke
  stops the loading screen and moves the live NPC 3 m in front of the actor
  (`spatial_move()` included) because the archive harness otherwise renders the
  menu/loading background and the one live NPC spawns under the map. A normal
  gameplay session does not need this placement.
- One active PhysX ragdoll per level. A second NPC fails over to ODE.
- No save/load, no streaming of the whole map, no animation-driven ragdoll.
- The shapeless/zero-mass root promotion is an approximation for the OGSR
  capture contract.
- Static collision is a bounded fragment, not the whole level. Bodies leaving
  the 48 x 24 x 48 m box lose real collision.
- `Hinge2` remains unsupported; no real capture contained one.
- PhysX DLLs and screenshots are external artifacts and are not tracked.
