## Findings and conditions

### F1 — Baseline UI startup crash: MERGE HOLD / gameplay BLOCKED

Identical logical crash site `CDialogHolder::OnFrame` in `UIDialogHolder.cpp:220` (`wnd->Update()`) → `CMainMenu::OnFrame`, `0xC0000005`, occurs in pure `origin/prypiat` feature-off baseline *and* integrated feature-off/feature-on. Baseline newgame/station logs and five minidumps validate reproduction. The crash is **not specific to PhysX being present**, but root cause remains **unknown**; identical stack does not itself establish identical memory corruption mechanism. Normal gameplay startup without diagnostic workaround is NOT ACCEPTED.

**Next:** isolate `TopInputReceiver()` and menu dialog ownership/lifetime, log receiver pointers/construct/destruct, classify use-after-free/dangling/UI sequencing from WinDbg or equivalent with symbols; create minimal baseline UI fix **separate from PhysX**, test feature-off baseline, then re-test integration feature-on/off without workaround. Do not ship workaround as production fix.

### F2 — Evidence cannot prove unpushed commit or binary provenance end-to-end

Full diff and source blobs checked to meaningful depth, but the Git object `16b8822` and built EXE/DLL files are not accessible in this review. Before merge verify `git show --format=fuller`, `git diff base...HEAD --check`, file manifest, source commit provenance, built binary SHA and actual signed-off review commit, then publish **only** a dedicated integration review branch.

### F3 — Fixture/test policy acceptable with limits

Mandatory CTest uses a hand-authored synthetic humanoid (11 bodies, 10 joints). Optional real capture returns SKIPPED (77) when absent; properly represented as 10 PASS + 1 SKIPPED. Preserve real fixture optional for CI and retain real-data validation as a separate runtime evidence requirement. CMake also sets `SKIP_RETURN_CODE 77` on mandatory synthetic test: the path does not use 77 in normal invocation but should avoid making the mandatory test skippable unnecessarily (non-blocking cleanup).

### F4 — Mixed callback scenario not evidenced

New script supports `--mixed-log` but only supplied v1-only and v2-only logs were rerun. V1 and V2 process exclusivity may prevent simultaneous worlds; verify any supported sequential transitions/lifetime before full G5 acceptance. Do not claim mixed mode PASS.

### F5 — No-vis crash unresolved historical observation

`IR_OnMouseMove` historical R1 crash not reproduced in three sessions; this supports local stability but does not prove it is impossible. Keep as MONITOR/UNRESOLVED pending normal gameplay.

DX12 smoke is green on evidence, but **does not validate end-to-end DX12 runtime**.
