## F1 — Actual PhysX COM

### До

- Импульс и логи использовали capture COM из `RagdollBodyDesc::centerOfMass`.
- После `updateMassAndInertia()` эффективный COM promoted root находится в
  mass frame PhysX и может сильно отличаться от capture COM.
- Нулевой `bone_space_position()` неявно означал «нет точки» и подменялся COM.

### После

- Добавлен POD `BodyMassProperties` и `PhysXRagdollWorld::massProperties()`
  (`Layers/PhysicsPhysX/include/physics_physx/physx_ragdoll_world.h:43`,
  `src/physx_ragdoll_world.cpp:1286`).
- Источник истины — `actorWorld * getCMassLocalPose()`; возвращаются масса,
  actor world, mass world, локальный COM, мировой COM и главные моменты.
- C ABI:
  - `OgsrPhysXRagdollGetBodyMass` (`physx_ragdoll_c.h:242`,
    `physx_ragdoll_c.cpp:719`);
  - `OgsrPhysXRagdollApplyCentralImpulse` (`physx_ragdoll_c.h:237`,
    `physx_ragdoll_c.cpp:678`).
- Игровой путь: `OgsrPhysXRagdollApplyBoneHit` всегда использует явную
  bone-space точку (`ogsr_physx_ragdoll.cpp:704`), а центральный толчок идёт
  отдельным `OgsrPhysXRagdollApplyCentralImpulse` (`...:806`) через actual COM.
- Body ID сверяется с ответом PhysX; для bone/merged используется фактический
  `actorWorld` из mass properties, а не потенциально устаревший `lastBodyWorld`.
- `(0,0,0)` больше не является sentinel: ноль — валидная точка в начале кости.
- Дополнительных импульсов и компенсирующих torque нет.

```cpp

// after
```

## F2 — Visual lifecycle

### До

`cNameVisual_set()` сразу публиковал новую visual, затем вызывал
`OnBeforeVisualChange()` и удалял старую модель. При ошибке создания или
исключении старое состояние уже было потеряно.

### После

`xr_object.cpp:23` реализует порядок:

1. новая модель создаётся во временном `new_v`;
2. при `nullptr` старая visual остаётся текущей;
3. `OnBeforeVisualChange()` вызывается, пока старая visual ещё текущая;
4. после cleanup наследуется только глобальный update callback/param;
5. новая visual публикуется;
6. старая освобождается;
7. вызывается `OnChangeVisual()`.

```cpp
// before: publish first, then cleanup
renderable.visual = Render->model_Create(*N);
OnBeforeVisualChange();
Render->model_Delete(old_v);
// after: create temporary, cleanup while old is current, then publish
new_v = Render->model_Create(*N);
if (!new_v) return;
OnBeforeVisualChange();
renderable.visual = new_v;
Render->model_Delete(old_v);
```

Per-bone callbacks не копируются: они принадлежат старому skeleton. PhysX
cleanup сбрасывает только свои callback slots по проверке
`callback()/callback_param()`.

### Runtime checks

PhysX ownership:

```text
old_per_bone_callbacks=47
pre-visual release
PhysX ragdoll instance released
visual replacement completed without crash global_callback_preserved=1 new_per_bone_callbacks=0
repeated visual cleanup completed without crash
```

ODE ownership:

```text
replacing visual of ODE NPC id=10608 old=[...stalker_neutral_1] new=[...stalker_soldier_2] shell=1
ODE visual replacement completed without crash shell=1
```

Null visual: удаление NPC идёт через `cNameVisual_set(nullptr)`; лог
`pre-visual release` + `instance released` подтверждает путь удаления.

Ограничение: `CModelPool::Instance_Load` для отсутствующего ассета вызывает
`FATAL`, поэтому failed model creation нельзя безопасно воспроизвести в
текущем runtime без изменения model pool. В `cNameVisual_set()` есть
defensive `if (!new_v) return;`; это code-level проверка, не runtime-тест.

## F3 — Contact counter lifetime

`RagdollContactCollector` разделён:

- `resetStep()` — `contactCount`, `found`, `persist`, `lost`,
  `totalImpulse`, `maxPenetration` (`physx_ragdoll_world.cpp:136`);
- `resetScene()` — дополнительно `activePairs = 0` (`...:146`).

`resetScene()` вызывается в `clearScene()` и `initialize()`; `resetStep()` —
только в `simulateFixed()`. Уничтожение мира и новый lifecycle не наследуют
старые active pairs.

```cpp
// before: one reset for both lifetimes
contacts.reset();
// after
contacts.resetStep();  // per simulation step
contacts.resetScene(); // scene destruction / new lifecycle, clears activePairs
```

Regression `testContactCounterLifetime` (`tests/test_main.cpp:992`):

1. тело касается пола → `activeContactPairs > 0`;
2. `world.destroy()` → `activeContactPairs == 0`;
3. новый мир с телом в воздухе → до первого шага `activeContactPairs == 0`.

## F4 — Technical failures fail every variant

`test_stability.cpp` теперь разделяет:

- `technicalOk` — создание, шаги, finite values, завершение 600 шагов,
  CSV open/write/flush/close;
- `acceptanceOk` — thresholds;
- `required` — только для acceptance gate.

Любой technical failure даёт exit 1 независимо от `required`. Optional
исторический вариант может не пройти thresholds, но не может «успешно»
завершиться при ошибке исполнения.

```cpp
// before
if (!runVariant(...) && variant.required) allRequiredPassed = false;
// after
if (!technical) allTechnicalPassed = false;
else if (variant.required && !summary.acceptanceOk) allRequiredAcceptancePassed = false;
return (allTechnicalPassed && allRequiredAcceptancePassed) ? 0 : 1;
```

## ODE risk: KillHit order

До F1–F5 порядок был изменён и для feature-off: death motion выбирался раньше
`CreateShell()`. Теперь `CharacterPhysicsSupport.cpp:451` использует
изолированный `#ifdef OGSR_PHYSX_RAGDOLL`:

- feature-on: death motion → PhysX attempt → ODE fallback `CreateShell()`;
- feature-off: **исходный порядок** `CreateShell()` → death motion.

Feature-off Debug и Release собираются, P2-символов в бинаре нет. Runtime
feature-off по-прежнему блокируется падением архивного `MainMenu` до старта
уровня; это не PhysX path и не выдается за PASS.
