## Why the all-human rollout may be fast

Reviewed I3 source, not a speculative new feature:
- `ogsr_engine/xrGame/ogsr_physx_runtime.cpp` has explicit `-physx_all_humans` parsing. When enabled, it requests the PhysX ragdoll V2 multi-instance backend and the free ragdoll death path. The experimental cap `-physx_max_ragdolls` is bounded **2…40 concurrent**; the source default is **2**.
- `ogsr_engine/xrGame/CharacterPhysicsSupport.cpp::TryActivatePhysXRagdoll` already attempts the PhysX shell transition for real stalker NPCs, without simplified visuals. It checks owner state, scene, matching, live count, static tiles/bounds and falls back to **existing ODE** if unsupported.
- V2 ownership, release, collider callbacks and DLL lease lifecycle already have targeted I3 evidence; this **is not** a demonstrated high-population gameplay PASS.
- All-human eligibility currently means **human `CAI_Stalker` after death**, not mutants, living NPC motion/AI, physics of every dynamic object, or unlimited ragdoll bodies.
- Feature flag `OgsrPhysXRagdoll=true` remains opt-in; do not change default to enabled at the premerge stage.

### Critical coverage distinction

`-physx_all_humans` means **attempt PhysX for each eligible stalker**, not guarantee every corpse uses PhysX. The cap, unsupported rig/visual, static coverage, scene load/ABI, or runtime errors correctly produce ODE fallback. Measure how many attempted, succeeded and fell back by reason; never claim 100% PhysX coverage based only on flag presence.
