## 3. Frozen C ABI v2

### 3.1. Calling convention and packing

- `OGSR_PHYSX2_CALL` = `__cdecl`; v1 exports also use default `__cdecl`.
- `OGSR_PHYSX2_API` = `dllexport` in the DLL, `dllimport` for consumers,
  empty for static/header-only tests.
- `#pragma pack(push, 8)`; offsets asserted with `_Static_assert` (C11) /
  `static_assert` (C++).
- No STL, PhysX or X-Ray types cross the header.

### 3.2. Sizes and offsets

| Type | Size | Fields (offset) |
|---|---:|---|
| `OgsrPhysX2SceneHandle` | 8 | `slot` 0, `generation` 4 |
| `OgsrPhysX2RagdollHandle` | 16 | `sceneSlot` 0, `sceneGeneration` 4, `instanceSlot` 8, `instanceGeneration` 12 |
| `OgsrPhysX2ApiInfo` | 32 | `structSize` 0, `magic` 4, `abiMajor` 8, `abiMinor` 12, `capabilityFlags` 16, `maxScenes` 20, `maxInstancesPerScene` 24, `reserved0` 28 |
| `OgsrPhysX2SceneConfig` | 48 | `structSize` 0, `fixedTimestep` 4, `gravityY` 8, `workerThreads` 12, `maxSubsteps` 16, `solverPositionIterations` 20, `solverVelocityIterations` 24, `contactOffset` 28, `restOffset` 32, `enableStabilization` 36, `collectContacts` 40, `maxInstances` 44 |
| `OgsrPhysX2RagdollInstanceConfig` | 32 | `structSize` 0, `linearDamping` 4, `angularDamping` 8, `staticRootDensity` 12, `promoteStaticRoot` 16, `disableSelfCollision` 20, `collisionGroup` 24, `collisionMask` 28 |
| `OgsrPhysX2StepResult` | 40 | `structSize` 0, `steps` 4, `droppedSteps` 8, `reserved0` 12, `stepIndex` 16, `frameId` 24, `simulatedSeconds` 32, `droppedSeconds` 36 |

Generation fields are full 32-bit values. `0` is invalid. No packing/truncation
exists.

### 3.3. `GetApiInfo` contract

| Caller `structSize` | Behavior |
|---|---|
| `< 32` | return `0`; no field writes; caller capacity is not exceeded |
| `== 32` | fill all v2.0 fields; set `structSize = 32`; return `1` |
| `> 32` | fill only the first 32 bytes; leave extension bytes untouched; set `structSize = 32`; return `1` |
| `nullptr` | return `0` |

P3.1-A-R1 values:

- `magic = 0x4F505832` (`"OPX2"`);
- `abiMajor = 2`, `abiMinor = 0`;
- `capabilityFlags = 0` — production scene/multi capabilities are **not**
  advertised because the backend does not implement them;
- `maxScenes = 4`; `maxInstancesPerScene = 64` — **per scene**;
- `reserved0 = 0`.

### 3.4. Production DLL exports

`dumpbin /exports ogsr_physx_runtime.dll` (Release):

- 19 exported names total;
- 12 v1 ragdoll exports;
- 6 generic v1 runtime exports;
- 1 v2 export: `OgsrPhysX2GetApiInfo`;

The header declares future v2 entry points for ABI freeze, but the P3.1-A-R1
DLL does not export them. The loader verifies this and fails closed.

## 4. F1 — generation lifetime

### 4.1. Process-wide allocators

- `GenerationAllocator` is a process-wide 32-bit allocator within the
  DLL/runtime lifetime, separate for scene and instance generations.
- `allocate()` returns `1..UINT32_MAX`; `0` means exhausted/invalid.
- After `UINT32_MAX` is issued, the allocator is exhausted; it never wraps to
  1 and never reissues old generations.
- `resetGenerationAllocatorsForTest()` exists only for sequential unit tests.
- Registry construction, level reload or registry destruction does **not**
  reset the allocators.

### 4.2. Handle identity

- A scene handle is `{sceneSlot, sceneGeneration}`; an instance handle is
  `{sceneSlot, sceneGeneration, instanceSlot, instanceGeneration}`.
- A registry B created after registry A receives new global generations, so
  old A handles fail the scene-generation check before any instance access.
- The public handle layout and C ABI are unchanged.

### 4.3. Slot lifecycle

1. `createScene`: allocate a global scene generation; call
   `hooks.createScene`; store `{slot, generation, backend}`.
2. `destroyScene`: validate; destroy its instances; destroy scene backend;
   clear `alive`/`backend`; if the assigned generation was `UINT32_MAX`, mark
   the slot retired.
3. `createInstance`: validate scene; find a free slot in **that scene's**
   instance table; allocate global instance generation; check collision ID;
   call scene-aware `hooks.createInstance`; publish handle.
4. `destroyInstance`: validate scene generation first, then instance
   generation/binding; destroy backend; clear slot; retire if generation was
   `UINT32_MAX`.
5. Destroy does not perform a dangerous `generation++`. Identity comes from
   the global allocator; invalidation comes from clearing `alive` and the new
   generation on reuse.

### 4.4. Negative test

`testRegistryARejectsHandlesFromRegistryB`:

- registry A creates scene/instance and is destroyed;
- registry B creates new scene/instance;
- B rejects old A scene and instance handles, returns zero collision ID and
  refuses destroy;
- B's own handles remain alive.

## 5. F2 — scene-aware backend hooks

Internal C++ contract:

```cpp
struct RagdollSceneContext
{
    OgsrPhysX2SceneHandle handle{};
    void* backend = nullptr;
};

virtual bool createInstance(const RagdollSceneContext& scene,
                            void** outInstance, std::string* error) = 0;
virtual void destroyInstance(const RagdollSceneContext& scene,
                             void* instance) = 0;
```

- The registry validates the scene and passes its handle + backend context.
- Backend cannot create an instance without an owning scene context.
- `destroyInstance` receives the same context, so backend cleanup is
  scene-scoped.
- `testSceneAwareHooks` creates two scenes and instances in each, verifies
  handle/backend correspondence, destroys one scene and confirms the other
  scene and its instances survive; a failed create in the surviving scene
  does not change its resources.

## 6. F3 — deterministic teardown

- `bool shutdown(std::string* error = nullptr)` is the explicit game-facing
  teardown contract.
- It destroys every live instance first, then its scene, for every active
  scene; it invalidates handles and is idempotent.
- `isShutdown()` and `hasActiveResources()` expose state.
- `~RagdollRegistry()` calls `shutdown()` as a safety net, so active backend
  objects are not silently dropped. The game must remove bone callbacks before
  calling `shutdown`; the registry cannot know about `IKinematics`.
- After shutdown, `createScene`/`createInstance` fail, and old handles cannot
  reach backend resources.

`testShutdown`:

- scene + two instances → shutdown → exactly two instance destroys and one
  scene destroy;
- second shutdown is safe and does not destroy again;
- handles invalid; create after shutdown rejected.

`testDestructorShutdown` verifies the destructor path also performs two
instance destroys and one scene destroy.

## 7. F4 — per-scene capacity

- Each `SceneSlot` owns `std::vector<InstanceSlot>` sized to
  `RagdollRegistryConfig::instanceCapacity`.
- `GetApiInfo.maxInstancesPerScene = 64` is the capacity of **each scene**.
- Total registry capacity is `sceneCapacity * instanceCapacity` (4 × 64).
- `instanceSlot` in the public handle is a per-scene index.
- `testPerSceneCapacity` creates two scenes, fills each with 64 instances,
  verifies the 65th create fails per scene, releases one slot and reuses it,
  then destroys one scene and confirms the other scene's 64 instances remain
  alive.

## 8. F5 — DLL lifetime

`V2ModuleLease` is the RAII owner for `HMODULE` + `V2ApiTable`:

- `load(path)` owns the module;
- `negotiate()` stores the table only on `Ready`;
- `unload()` clears `V2ApiTable` **before** `FreeLibrary`, so lease-owned
  function pointers are invalidated before the module is unloaded;
- destructor calls `unload()`;
- `api()` is valid only while `isLoaded()` and `isApiValid()` are true;
- `negotiate()` stores the table in the lease and returns an empty
  `result.api`, so a result copy cannot outlive `unload()`;
- copied function pointers are a caller contract violation.

`testModuleLease` loads the mock v2 DLL, negotiates `Ready`, verifies the
lease table and the empty result table, unloads, verifies the table is empty
and the lease reports unloaded, calls unload again (safe), verifies
negotiation after unload fails closed, reloads and renegotiates.

## 9. Registry lifecycle and errors

### 9.1. Ownership

- `RagdollRegistry` owns slots, generations, validity and collision IDs.
- `RagdollRegistryHooks` owns backend resources and receives scene context.
- Registry has no PhysX pointers and never dereferences one.
- Single-threaded; all calls on the game/main thread.

### 9.2. Error/retry policy

| Error | Safe to repeat? | Required action |
|---|---|---|
| Stale/invalid scene or ragdoll handle | Yes, no-op/error | Reacquire a live handle or destroy the level |
| Double destroy | Yes, no-op/error | Treat as already destroyed |
| Scene backend create failure | Yes, after backend fix | Retry; slot not consumed |
| Instance backend create failure | Yes, after backend fix | Retry; scene/other instances untouched |
| Collision ID exhaustion | No | Scene cannot create more instances; recreate scene/teardown |
| Scene/instance generation exhaustion | No | Allocate no more objects; recreate runtime/DLL or use a fresh process |
| `SceneDestroy` stale handle | Yes, no-op/error | Do not use old scene; new scene has new generation |
| Registry shutdown | Yes, idempotent | No further create/destroy; handles invalid |

## 10. Fail-closed loader

Negotiation order:

1. Resolver must be non-null.
2. Resolve `OgsrPhysX2GetApiInfo`; missing → `MissingApiInfo`.
3. Call it with `structSize = 32`.
4. Validate return value, `structSize == 32`, magic, major, minor, required
   capabilities, minimum scene/instance capacity.
5. Resolve every mandatory v2 export.
6. Only after all checks return `Ready` and publish `V2ApiTable`.

Only `GetApiInfo` is called before the table is complete. No
`SceneCreate`/`SceneStep`/`RagdollCreate` call occurs during negotiation.

Negative matrix:

| Case | Result/status |
|---|---|
| v1-only DLL | `MissingApiInfo` |
| actual v2-info DLL + v1 exports | `MissingExport` (caps 0) or `MissingCapabilities` (full caps) |
| no `OgsrPhysX2GetApiInfo` | `MissingApiInfo` |
| missing mandatory v2 symbol | `MissingExport` |
| wrong magic | `BadMagic` |
| unsupported major/minor | `UnsupportedMajor` / `UnsupportedMinor` |
| missing required capabilities | `MissingCapabilities` |
| invalid `structSize` | `InvalidInfoSize` |
| partial negotiation | `MissingExport`, empty table |
| null resolver | `NullResolver` |
| full mock v2 DLL | `Ready`, complete table |
| module lease unload | table empty; negotiation after unload fails |

Mock DLLs (`mock_physx_runtime_v1`, `mock_physx_runtime_v2`,
`mock_physx_runtime_v2_missing`) are test-only and are not shipped.
