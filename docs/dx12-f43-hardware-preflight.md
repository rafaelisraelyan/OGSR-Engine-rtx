# F4.3 — Подготовка Jupiter A/B

Launcher запускает банковый режим по умолчанию. `-AdaptiveShadows` включает адаптивные локальные тени. `-AdaptiveShadowBudgetBytes` задаёт общий лимит физических страниц обоих слотов, включая временный пик замены. Каждый слот получает до половины конечного лимита. `-AdaptiveShadowReserveBytes` оставляет место другим ресурсам в наблюдаемом DXGI LOCAL бюджете. Ноль для лимита означает режим без адаптивных страниц, а значение по умолчанию оставляет ограничение за DXGI. Эти величины не резервируют память в ОС.

## Команды после согласования

Рабочий каталог — корень экспериментального checkout. Укажите проверенный runtime Jupiter в `GameRoot` и итоговый бинарник в `Exe`.

```powershell
$launcher = '.\tools\dx12\run-f43f-jupiter.ps1'
$common = @{
    GameRoot = '<проверенный runtime Jupiter>'
    Exe = (Resolve-Path '.\bin_x64\xrEngine.exe').Path
    Metrics = $true
    SunShadowProfile = 'Balanced'
    SunCascades = 3
    SunShadowResolution = 2048
    SunShadowDistance = 160
    GR = 'parallel'
    GRWorkers = '2'
    GRGrain = 256
    CommandLists = 'parallel'
}
$adaptive = @{
    AdaptiveShadows = $true
    AdaptiveShadowBudgetBytes = 536870912
    AdaptiveShadowReserveBytes = 1073741824
}

# A — banked
& $launcher @common

# B — adaptive, 512 МиБ на страницы и 1 ГиБ резерва
& $launcher @common @adaptive

# Короткая проверка корректности отдельно от замера A/B
& $launcher @common @adaptive -Validation
```

Параметр `-Preflight` к любой из команд проверяет пути, сохранение, профиль и наличие архивов и завершает скрипт до запуска процесса. Основная геометрия Jupiter может находиться в архивах. Проверка наличия файлов не подтверждает, что эта сборка загрузит сцену.

Во всех прогонах загружайте `b23_jupiter.scop` и используйте тот же `user_ogsr.ltx`. Сохраните профиль перед первым запуском и проверяйте его хэш или восстанавливайте исходный профиль перед следующим прогоном. После загрузки зафиксируйте камеру на месте 20 секунд, затем повторите короткий заранее согласованный маршрут без смены графических настроек. Сравнивайте одинаковые участки и время от загрузки сохранения. Сверяйте погоду, время суток и разрешение по фактическим записям. Короткий прогон с GBV закончите после тех же контрольных видов. Храните лог каждого запуска отдельно.

Строка `ph_dx12_shadow_preflight:` содержит поля key=value при первом кадре и каждые 120 presents. Сверьте `requested_mode`, `actual_mode`, `fallback` и число страниц. Поля байт страниц и ёмкость хвоста относятся к адаптивной арене. `gpu_present` указывает кадр, для которого уже доступен GPU-результат, и может отставать от текущего `present`. Не используйте запуск с GBV для A/B таймингов.
