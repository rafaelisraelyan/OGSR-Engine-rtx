> **Superseded by `docs/p2.2a-final-code-verification.md`.** The final-code

> splits contact reset lifetime, hardens stability technical failures and
> regenerates A/B. Keep this file as the P2.2A-FIX history.

кости в world space, а PhysX callbacks/state освобождаются до удаления старой

остальное ниже проверено и имеет артефакты.

## 2. Импульс

`OgsrPhysXRagdollApplyHit` больше не использует `lastBodyWorld[body].translation`
как точку приложения.

Порядок:

1. `hit.bone()` → `capture.boneBody` / `boneKind`.
2. Для обычной кости: `boneWorld = lastBodyWorld[body]`.
3. Для merged-кости (pelvis/spine): `boneWorld = lastBodyWorld[body] * mergedLocal`.
4. Для frozen-кости: `boneWorld = entityWorld * animationBoneModel`.
5. `hit.bone_space_position()` переводится в world **один раз**:
   `hitWorld = transformPoint(boneWorld, boneLocal)`.
6. Если `bone_space_position()` нулевой, используется мировой COM:
   `transformPoint(bodyWorld, bodyDesc.centerOfMass)`.
7. Импульс берётся из `hit.direction() * hit.phys_impulse()`; направление уже
   world-space, повторного преобразования нет.
8. В PhysX уходит `addForceAtPos(..., eIMPULSE)` ровно один раз.

Логируется:

```text
ph_ragdoll: hit impulse body=0 bone=2 hit=(253.382,19.858,548.645)
com=(253.382,19.858,548.645) lever=(0.000,0.000,0.000)
impulse=(0.00,1.94,7.76) angular=(0.00,0.00,0.00)
```

В реальном smoke-попадании `SHit` синтетический и точка попадания совпала с
COM, поэтому `lever=0`. Это не доказывает offset-ветку; она покрыта unit-тестом:

- импульс в COM → `maxAngularSpeed < 1e-4`, `externalImpulses == 1`;
- импульс в стороне от COM `(1,0,0)` при `Iyy=0.4` → аналитически
  `ω = 1/0.4 = 2.5 rad/s`;
- поворот родительского body не меняет длину bone-space offset;
- merged pelvis/spine использует `bodyWorld * mergedLocal`, а не двойной
  transform;
- frozen bone использует `entityWorld * animationBoneModel`;
- нулевая bone-space позиция даёт мировой COM.

## 3. Visual lifecycle

Добавлен hook `CObject::OnBeforeVisualChange()`, который вызывается **до**
`Render->model_Delete(old_v)` в обеих ветках `cNameVisual_set`
(`xr_object.cpp:47-53`).

`CPhysicsShellHolder::OnBeforeVisualChange` передаёт управление
`CCharacterPhysicsSupport::OnBeforeVisualChange`
(`CharacterPhysicsSupport.cpp:116`). Если владелец — PhysX:

- `ReleasePhysXRagdoll()` сбрасывает per-bone callbacks на старой
  `IKinematics`, инвалидирует bones и уничтожает PhysX instance;
- `m_physx_ragdoll = nullptr`, `m_owner = ownerNone`,
  `fl_skeleton_in_shell = false`;
- повторный вызов безопасен: `ReleasePhysXRagdoll` проверяет null.

Для NPC без PhysX hook ничего не делает, обычный visual lifecycle не изменён.

## 4. Root mass

`PhysXRagdollWorld::createActors()` теперь проверяет:

- `simulationShapeCount > 0`;
- `bool` результат `PxRigidBodyExt::updateMassAndInertia()`;
- `mass > 0` и finite;
- все три главных момента инерции `> 0` и finite;
- `getCMassLocalPose().isValid()`.

При любой ошибке возвращается `false` до `created = true`, поэтому ownership
не коммитится, а `clearScene()` освобождает сцену.

Плотность оставлена **300 kg/m³**. На реальном fixture:

- root mass: **9.87639 kg**;
- total mass: **92.2128 kg**;
- `root_dynamic=1`, `root_body=0`.

Два пересекающихся сферических shape дают **сумму mass properties**, а не массу
геометрического объединения. Поэтому 9.876 kg — это shape-density
аппроксимация, а не точная масса таза/позвоночника. Это явно зафиксировано и не
выдаётся за ODE mass readback (ODE root mass по контракту равна нулю).

Negative test: root с `StaticRoot`, `promoteStaticRoot=true` и только
`NoPhysics` shapes отклоняется; ошибка непустая. Hinge2 также отклоняется.

## 5. Energy diagnostics

Исправлена система отсчёта:

```text
massWorld = actorWorld * getCMassLocalPose()
ω_mass    = massWorld.q.rotateInv(ω_world)
E_rot     = 0.5 * (Ixx*ωx² + Iyy*ωy² + Izz*ωz²)
E_pot     = -mass * dot(gravity, COM_world - reference)
E_total   = E_kin + E_pot
```

`getMassSpaceInertiaTensor()` — главные моменты; вращение mass frame берётся из
`massWorld.q`, а не из actor frame. Потенциальная энергия считается по COM и
полному вектору gravity (X/Y/Z), а не только по `-gravity.y`.

Unit tests покрывают:

- повёрнутый mass frame;
- смещённый COM;
- gravity с X и Z компонентами;
- статическую позу (`KE = 0`);
- известную линейную скорость;
- известную угловую скорость вокруг главной оси;
- finite-значения и единицы J.

CSV содержит столбцы:

```text
step,kinetic,potential,total,max_angular,anchor_error,limit_error,
contacts,found,persist,lost,active_pairs,contact_impulse,penetration,
awake,dynamic,external_impulses
```

Runtime Release (лог `xray_gr_25-10-26_06-11-03.log`):

```text

limit=0.0093 contacts=7 found=0 persist=6 lost=0 active=6 pen=0.0001 awake=11/11
```

Абсолютные PE/Total нельзя сравнивать со старым P2.2A отчётом: изменились

`limit`, `awake`.

## 6. Stability-тест: ложный PASS устранён

## 7. Contact diagnostics

Разделены:

- `contactFound` — `eNOTIFY_TOUCH_FOUND`;
- `contactPersist` — `eNOTIFY_TOUCH_PERSISTS`;
- `contactLost` — `eNOTIFY_TOUCH_LOST`;
- `activeContactPairs` — найденные минус потерянные;
- `contactCount` — число контактных точек в найденных/продолжающихся парах;
- `totalContactImpulse`, `maxPenetration`;
- `awakeBodies`, `dynamicBodies`.

В filter flags добавлены `eNOTIFY_TOUCH_PERSISTS` и `eNOTIFY_TOUCH_LOST`.
PhysX может не присылать persistent callbacks для sleeping bodies, поэтому
`contacts=0` при `awake=0` **не** трактуется как отсутствие опоры. В Release
логе видно `contacts=0, active=11, awake=0/11`: опора есть, событий нет.

## 8. Dead fixture

Fixture `zat_b42_mayron`:

- live `sim_default_stalker_26525`: max anchor error **0.00325428 m** (joint 2);
- dead `zat_b42_mayron`: max anchor error **1.05326 m** (joint 4).

Проверены этапы: capture из активной ODE shell, world/model transforms,
root-to-entity mapping, joint local frames, initial body poses, ориентация shell
относительно visual, bind pose vs текущая динамическая поза.

Конкретные world-space концы anchor до первого шага:


Вывод: dead fixture представляет уже активную ODE shell с позой, которая не
совпадает с bind/initial pose. Поддерживаемый handoff ограничен **живой
анимированной позой**. Dead fixture оставлен только как diagnostic; projection
и damping произвольно не увеличивались. Он не считается общим PASS.

измеримого динамического эффекта не дали. Полезный эффект self-collision
**не заявляется**.

0.5→9.876 kg, solver 8/2→16/4, damping 0→0.05/0.2, а также исправленной
энергетической моделью. Поэтому сравнивать можно динамику (ω, anchor, limit,
awake), но не абсолютные J.
