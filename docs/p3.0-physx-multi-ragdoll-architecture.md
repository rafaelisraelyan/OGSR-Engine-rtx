## 0. Scope, status and invariants

### 0.1. Что означает R1

R1 — doc-only исправление ADR после независимого аудита. Замечания F1–F5
считаются **FIXED в архитектурном контракте**, но не в реализации: кода v2
ещё нет. Проверка исполнения контрактов — предмет P3.1 и повторного ревью.

### 0.2. Неизменяемые инварианты

- Модель **A**: одна PhysX scene на уровень + N generation-safe ragdoll
  instances. Вариант B (scene на каждый ragdoll) — только аварийная изоляция
  для отладки, не production-модель.
- Fixed timestep `0.01` с, solver `16/4`, damping `0.05/0.2`, текущие массы и
  joints не меняются без отдельных измерений.
- **Один dynamic object — один authoritative solver.** ODE и PhysX не владеют
  одним NPC одновременно.
- v1 P2.2A path остаётся доступным и неизменным; v2 не ломает v1 ABI.
- На уровне активен ровно один PhysX path: v2 multi, v1 single или ODE.
  Смешивание v1/v2 handles в одной цепочке вызовов запрещено.
- Collision filter shader не читает process-global mutable state.
- Все операции проверяют handle до обращения к PhysX pointers.
- P3.0 PASS присваивается только после независимого review; R1 такого права
  не имеет.

Текущая схема — **B-single: одна PhysX scene на один ragdoll**, но игра
держит **один** runtime и **один** активный instance. Второй NPC намеренно не
получает PhysX (`CPS.cpp:1276`), а C ABI `RagdollCreate` уничтожает
предыдущий world (`physx_ragdoll_c.cpp:528`). Шаг выполняется до
`Objects.Update`, публикация поз — внутри `in_UpdateCL`; это правильная
основа для v2, но контракт идемпотентности шага сейчас не выражен.

- `LoadLibraryA("ogsr_physx_runtime.dll")`.
- `GetProcAddress` по каждому v1 имени, cast к v1 typedef, проверка всех

## 2. Confirmed limitations (file:line)

1. **Single-instance gate:** `CPS.cpp:1276`
   `if (!OgsrPhysXRagdollRuntimeAlive() || OgsrPhysXRagdollRuntimeHasInstance()) return false;`
   — второй NPC принудительно уходит в ODE.
2. **Single active flag:** `runtime.cpp:102`, `runtime.cpp:281`; create
   сбрасывает `g_ragdoll_active=false` и ставит `true` (`runtime.cpp:873-888`).
3. **Create replaces the previous world:** `c.cpp:528` `runtime->world.destroy()`
   перед `world.create()` (`c.cpp:531`). Второй `RagdollCreate` уничтожит
   первый ragdoll.
4. **Destroy destroys the whole world:** `c.cpp:560` `world.destroy()` в
   `OgsrPhysXRagdollDestroy`; удаление одного NPC уничтожит scene и всех.
5. **Raw pointer handle:** `c.cpp:51-54`, `c.cpp:427`; stale handle —
   use-after-free, generation отсутствует.
6. **No per-instance identity in C ABI:** все операции `c.cpp:603-839` и
   `runtime.cpp:921-988` используют `g_ragdoll_handle`; нельзя адресовать
   второй instance.
7. **Scene/foundation per ragdoll:** `world.cpp:282-295`, `world.cpp:380-422`;
   каждый world создаёт свой `PxFoundation`, `PxPhysics`, `PxScene`,
   `PxDefaultCpuDispatcher`, floor и materials. Это вариант B с дублированием.
8. **Global filter flags:** `world.cpp:110-111`; `world.cpp:408-409`
   перезаписывает их при создании каждого world; filter shader читает глобалы
   (`world.cpp:121-129`). Два world с разными настройками конфликтуют.
9. **All ragdolls share `word3=1`:** `world.cpp:597`
   `setSimulationFilterData(PxFilterData(0,0,0,1))`; self-collision suppression
   сравнивает `word3` (`world.cpp:121`), поэтому при включении режима
   подавляются **все** ragdoll-ragdoll пары, не только self.
10. **Per-body `collisionGroup` не используется:** portable body имеет
    `collisionGroup` (`ragdoll.h:163-190`), но PhysX shape filter data его
    игнорирует (`world.cpp:597`).
11. **Static fragment per activation:** `ragdoll.cpp:724-772` запрашивает
    48×24×48 box вокруг NPC и вызывает `SetStaticMesh`; `applyStaticMesh`
    освобождает прежний static actor/mesh (`world.cpp:478-487`) и добавляет
    новый (`world.cpp:524-544`). В общей scene это заменит collision для всех.
    Замена нетранзакционная: старый mesh освобождается до успешного cook
    нового.
12. **Step per world:** `world.cpp:1225-1257` accumulator/`maxSubsteps`
    принадлежит world; `runtime.cpp:755` вызывает step один раз на кадр для
    одного world. При нескольких world каждый шагает отдельно, stepIndex
    расходятся; при общей scene нельзя вызывать step из `UpdatePhysXRagdoll`
    каждого NPC. Идемпотентность по frame ID не выражена.
13. **`workerThreads` игнорируется:** config имеет `workerThreads`
    (`physx_ragdoll_c.h:24-41`), но `PxDefaultCpuDispatcherCreate(2)`
    жёстко создаёт 2 worker'а (`world.cpp:401`).
14. **Save/load не сериализует PhysX:** `CCharacterPhysicsSupport::in_NetSave`
    (`CPS.cpp:373`) вызывает только `CPHSkeleton::SaveNetState`;
    `in_Load` (`CPS.cpp:159-167`) не восстанавливает PhysX. `net_SaveRelevant`
    проверяет `PPhysicsShell()` (`base_monster_net.cpp:16`,
    `ai_stalker.cpp:624`), а PhysX path держит `m_pPhysicsShell=nullptr`
    (`CPS.cpp:93`). Мёртвый PhysX NPC может выпасть из save.
15. **Level unload destroys the single runtime:** `runtime.cpp:453-473`;
    нет отдельного scene handle, который можно сохранить при удалении одного
    NPC.
16. **Нет ABI version negotiation (F1):** v1 loader (`runtime.cpp:394-450`)
    не запрашивает версию/capabilities. Черновик v2 из P3.0 повторно
    использовал v1 имена с новыми сигнатурами; это ABI-breaking и запрещено.
17. **Feature flag collision (F2):** `-physx_ragdoll_multi` уже занят
    diagnostic smoke-сценарием (`ragdoll.cpp:1374`); использовать его как
    production multi нельзя.
18. **Collision identity truncation (F3/F4):** предложенная схема
    `slot | generation << 16` усекает generation и допускает повтор
    identity; `word3` дублировал instance id, а не хранил flags. Глобальные
    filter-флаги и `word3=1` подавляют чужие ragdoll.
19. **Static fragment eviction by NPC center (F5):** eviction по центру NPC
    не учитывает union bounds, движение между шагами, contact/swept bounds и
    границы ячеек; release может произойти, пока фрагмент нужен живому
    instance.
20. **Teardown order не зафиксирован (F5):** bone callbacks, instance
    ownership и PhysX resources могут освобождаться в неверном порядке;
    `SceneDestroy` при живых callbacks/instances не описан.
21. **Step idempotence/order не зафиксированы:** один вызов step на кадр
    следует из текущего кода, но контракт «тот же frame ID не шагает
    повторно», dropped time при `maxSubsteps` и порядок относительно
    `Objects.Update`/pose publication не были явно описаны.

## 3. Option comparison

| Критерий | A: одна scene на уровень + N instances | B: scene на каждый ragdoll |
|---|---|---|
| Память | один foundation/physics/scene/dispatcher; общий static mesh; память ∝ числу тел | N foundation/physics/scene/dispatcher/floor/materials; static mesh дублируется |
| Fixed-step | один `simulate/fetch` на шаг; все instance видят один `stepIndex` | N независимых accumulator; шаги и `stepIndex` могут расходиться |
| Static collision | один level mesh / fragment registry; cook один раз | cook и память на каждого NPC; fragments дублируются |
| Межперсонажные столкновения | возможны в одной scene; управляются filter groups | невозможны: разные PxScene |
| Контактные события | один scene callback; attribution через actor→instance map | отдельный collector на world; проще attribution, но нет межперсонажных контактов |
| Синхронизация | один поток/один step; create/destroy вне simulate/fetch | независимые scene; глобальные filter-флаги создают скрытую связь |
| Create/destroy одного NPC | только его actors/joints; scene и другие живы | уничтожается/создаётся целая scene; другие не затронуты, но дорого |
| Level unload | destroy instances → destroy scene | destroy N scene; порядок и утечки сложнее |
| ABI/feature flags | v1 path отдельно, v2 scene/instance API с negotiation | v2 всё равно нужен; v1/v2 mixing risk выше |
| Соответствие P2.2A | требует scene/instance split, но даёт нужную семантику | ближе к текущему коду, но не удовлетворяет multi-требованиям |

**Рекомендация: A.** Аргументы — не удобство реализации, а:

- один fixed-step и один `stepIndex` для всех ragdoll;
- один static mesh и один foundation/physics/scene;
- возможность межперсонажных столкновений и корректных contact events;
- create/destroy одного NPC не трогает scene и других;
- глобальные filter-флаги исчезают (scene config + per-shape filter data);
- v1 single path остаётся отдельным и неизменным.

B оставляем только как аварийный fallback/изоляцию для отладки, не как
production-модель. Текущий код — B-single; его нельзя «включить на N», не
разделив scene и instance.

## 4. Recommended architecture

### 4.1. Компоненты

```text
OgsrPhysX2Scene (level, one per level)
  PxFoundation / PxPhysics / PxScene / PxDefaultCpuDispatcher
  PxMaterial set
  static level mesh + fragment registry (no runtime eviction in P3.1)
  scene contact collector + actor -> contact tag map
  step accumulator + lastFrameId + scene stepIndex + dropped time
  scene registry (slot/generation) + collisionInstanceId allocator
  immutable filter policy (PxSceneDesc.filterShaderData)

OgsrPhysX2RagdollInstance (one per dead NPC)
  public OgsrPhysX2RagdollHandle (sceneSlot/sceneGeneration/instanceSlot/instanceGeneration)
  collisionInstanceId (nonzero, unique among live instances)
  RagdollDescription / InitialState / last Pose
  PxRigidDynamic[] + PxD6Joint[]
  body -> actor map, body dynamic flags
  per-shape filter data (group/mask/id/flags)
  per-instance diagnostics counters
  contact tag lifetime owner
```

`PhysicsPortable` остаётся per-ragdoll data/contract (no PhysX/OGSR types).
`PhysicsPhysX` получает scene-класс и instance-класс; `PhysicsAdapterOGSR`
владеет mapping bone↔body и публикацией поз. `xrGame` владеет scene handle
уровня и instance handle в `OgsrPhysXRagdollState`.

### 4.2. Границы

- Scene не знает OGSR/ODE/DX; только PhysX + portable types.
- Instance не владеет scene/static mesh; scene не владеет NPC state.
- Adapter/OGSR владеет bone callbacks и `CCharacterPhysicsSupport`.
- C ABI — только POD handles/structs, без STL/PhysX.
- Game layer владеет выбором path (v2/v1/ODE), снятием bone callbacks и
  обнулением game references.
- Backend владеет PhysX resources, registry, contact tags и transactional
  create/destroy.

### 4.3. Один активный path на уровень

```text
- -physx_multi_instances + успешная v2 negotiation -> v2 multi
- иначе -physx_ragdoll <target> + полный v1 export set -> v1 single P2.2A
- иначе -> ODE
```

v2 scene и v1 runtime не существуют одновременно. При отказе v2 после
создания scene game обязан сначала выполнить `SceneDestroy`, дождаться
teardown и только затем инициализировать v1 или ODE. Смешивание v1/v2
handles в одной цепочке запрещено (см. §5.3, §6.3).

## 5. New API contracts

### 5.1. Handles and identity (F4)

Public handles — значения, не указатели. Никакой упаковки generation в 16 бит
и никакого `slot | generation << 16`.

```c
typedef struct OgsrPhysX2SceneHandle
{
    uint32_t slot;              /* index in scene registry */
    uint32_t generation;        /* full 32-bit, 0 = invalid */
} OgsrPhysX2SceneHandle;

typedef struct OgsrPhysX2RagdollHandle
{
    uint32_t sceneSlot;
    uint32_t sceneGeneration;
    uint32_t instanceSlot;
    uint32_t instanceGeneration;
} OgsrPhysX2RagdollHandle;
```

Правила:

- `generation` и `sceneGeneration`/`instanceGeneration` — полные 32-битные
  поля, без скрытого усечения.
- `generation == 0` зарезервирован для invalid; первая выдача — 1.
- `sceneGeneration` и `instanceGeneration` независимы.
- `collisionInstanceId` — **отдельное** 32-битное ненулевое значение, не
  public handle и не производная от slot/generation (см. §6.4).
- Handle сравнивается по всем полям; нулевой handle invalid.
- Public handle никогда не используется как collision identity.
- Все API принимают handle по значению; C++ слой валидирует registry до
  любого обращения к PhysX pointer.
- Stale handle не разыменовывает память; операция возвращает 0 и
  диагностическую ошибку.

| Поле | Владелец | Смысл | Инвалидация |
|---|---|---|---|
| `sceneSlot` | scene registry | индекс scene | `SceneDestroy` |
| `sceneGeneration` | scene registry | поколение scene | `SceneDestroy`/recreate |
| `instanceSlot` | instance registry | индекс instance | `RagdollDestroy` |
| `instanceGeneration` | instance registry | поколение instance | `RagdollDestroy`/reuse |
| `collisionInstanceId` | scene allocator | identity для filter/contact | `RagdollDestroy`; не reuse |

### 5.2. API contracts (v2)

| Операция | Контракт |
|---|---|
| `OgsrPhysX2GetApiInfo(info)` | единственный v2 export, который можно вызвать до negotiation; заполняет версию/capabilities; 1/0 |
| `OgsrPhysX2SceneCreate(config, &scene, err, n)` | transactional; при ошибке освобождает все partial resources, `scene` = zero; 1/0 |
| `OgsrPhysX2SceneDestroy(scene, err, n)` | освобождает все instances/static/contact/scene; инвалидирует handles; stale/invalid → 0 + error, no-op; повторный вызов не трогает новый объект |
| `OgsrPhysX2SceneIsAlive(scene)` | 1 только для valid slot+generation+alive |
| `OgsrPhysX2SceneSetStaticMesh(scene, mesh, err, n)` | level-owned mesh; transactional replacement; active instances не теряют collision; не вызывается на каждого NPC |
| `OgsrPhysX2SceneAddStaticFragment(scene, key, mesh, err, n)` | добавляет/заменяет фрагмент по 64-bit key; transactional; no runtime eviction в P3.1 |
| `OgsrPhysX2SceneStep(scene, delta, frameId, &result, err, n)` | ровно N fixed steps; idempotent по frameId; возвращает steps/droppedSteps/stepIndex; paused/0 delta → 0 steps |
| `OgsrPhysX2RagdollCreate(scene, definition, config, &handle, err, n)` | создаёт instance; при ошибке освобождает только свои actors/joints/tags; scene и другие живы; handle zero |
| `OgsrPhysX2RagdollDestroy(handle, err, n)` | освобождает только instance; инкрементирует generation; stale → 0 + error; никогда не удаляет новый объект на том же slot |
| `OgsrPhysX2RagdollIsAlive(handle)` | 1 только для valid scene+instance slot/generation+alive |
| `OgsrPhysX2RagdollGetPose(handle, pose, bodyWorld, maxBodies)` | valid+alive; bodyCount/stepIndex; stale → 0 |
| `OgsrPhysX2RagdollApplyImpulse(handle, body, pos, impulse, err, n)` | valid+alive+body range; stale/out-of-range → 0 |
| `OgsrPhysX2RagdollApplyCentralImpulse(handle, body, impulse, err, n)` | valid+alive+body range; stale → 0 |
| `OgsrPhysX2RagdollGetBodyMass(handle, body, mass, err, n)` | valid+alive+body range; stale → 0 |
| `OgsrPhysX2RagdollGetInfo(handle, info)` | valid+alive; per-instance info; stale → 0 |
| `OgsrPhysX2RagdollGetDiagnostics(handle, referenceHeight, diag)` | per-instance counters; stale → 0 |

Никаких «последний созданный»/implicit current instance. Каждая операция
принимает handle. v1 имена и сигнатуры не переиспользуются (см. §5.3).

### 5.3. C ABI v2 compatibility and negotiation (F1)

#### 5.3.1. Правило имен

- Все существующие v1 exports и их сигнатуры **остаются неизменными**.
- Все новые exports получают отдельный префикс `OgsrPhysX2` и новые имена.
- Запрещено повторно использовать v1 имя с другой сигнатурой, даже если
  «старый клиент всё равно не вызывает эту функцию».
- v2 использует существующие POD payload-структуры
  (`OgsrPhysXRagdollDefinition`, `OgsrPhysXRagdollPose`,
  `OgsrPhysXRagdollBodyMass`, `OgsrPhysXRagdollInfo`,
  `OgsrPhysXRagdollDiagnostics`) без изменения layout. Новые structs —
  только handles/config/step/api-info.
- v1 DLL и v2 DLL — один и тот же module `ogsr_physx_runtime.dll`; v2 DLL
  обязан сохранять все v1 exports и их поведение.

#### 5.3.2. Version/capability negotiation

Единственный v2 export, который разрешено вызывать до проверки версии, —
`OgsrPhysX2GetApiInfo`. Он заполняет структуру, по которой EXE решает,
совместим ли DLL.

```c
#define OGSR_PHYSX2_ABI_MAJOR 2u
#define OGSR_PHYSX2_ABI_MINOR 0u
#define OGSR_PHYSX2_API_INFO_MAGIC 0x4F505832u /* "OPX2" */
#define OGSR_PHYSX2_API_INFO_V0_SIZE 32u

#define OGSR_PHYSX2_CAP_SCENE                    (1u << 0)
#define OGSR_PHYSX2_CAP_MULTI_INSTANCE           (1u << 1)
#define OGSR_PHYSX2_CAP_INSTANCE_HANDLES         (1u << 2)
#define OGSR_PHYSX2_CAP_STATIC_FRAGMENTS         (1u << 3)
#define OGSR_PHYSX2_CAP_CONTACT_ATTRIBUTION      (1u << 4)
#define OGSR_PHYSX2_CAP_FRAME_IDEMPOTENT_STEP    (1u << 5)
#define OGSR_PHYSX2_CAP_PER_INSTANCE_DIAGNOSTICS (1u << 6)
#define OGSR_PHYSX2_CAP_CONFIGURABLE_WORKERS     (1u << 7) /* optional */

#define OGSR_PHYSX2_CAP_REQUIRED_P3_1 \
    (OGSR_PHYSX2_CAP_SCENE | OGSR_PHYSX2_CAP_MULTI_INSTANCE | \
     OGSR_PHYSX2_CAP_INSTANCE_HANDLES | OGSR_PHYSX2_CAP_STATIC_FRAGMENTS | \
     OGSR_PHYSX2_CAP_CONTACT_ATTRIBUTION | \
     OGSR_PHYSX2_CAP_FRAME_IDEMPOTENT_STEP | \
     OGSR_PHYSX2_CAP_PER_INSTANCE_DIAGNOSTICS)

typedef struct OgsrPhysX2ApiInfo
{
    uint32_t structSize;       /* in: caller sets sizeof/at least V0_SIZE */
    uint32_t magic;            /* out: OGSR_PHYSX2_API_INFO_MAGIC */
    uint32_t abiMajor;         /* out: 2 */
    uint32_t abiMinor;         /* out: >= 0 */
    uint32_t capabilityFlags;  /* out: OGSR_PHYSX2_CAP_* */
    uint32_t maxScenes;        /* out: >= 1 */
    uint32_t maxInstancesPerScene; /* out: >= 2 for P3.1 */
    uint32_t reserved0;        /* must be 0 */
} OgsrPhysX2ApiInfo;

int OgsrPhysX2GetApiInfo(OgsrPhysX2ApiInfo* info);
```

Порядок negotiation:

1. `LoadLibraryA` того же v1 module.
2. Разрешить и проверить generic v1 exports (как сейчас); при отсутствии —
   PhysX runtime недоступен, ODE fallback.
3. Если `-physx_multi_instances` не задан — v2 не загружается; работает
   v1/ODE path.
4. Если задан — `GetProcAddress("OgsrPhysX2GetApiInfo")`.
5. Вызвать `GetApiInfo` с `structSize = OGSR_PHYSX2_API_INFO_V0_SIZE`.
6. Проверить: return 1, `magic`, `abiMajor == 2`, `abiMinor >= 0`,
   обязательные capability bits, `maxScenes >= 1`,
   `maxInstancesPerScene >= 2`.
7. Только после успеха разрешить остальные обязательные v2 exports.
8. Если любой обязательный export отсутствует — залогировать имя, пометить
   v2 unavailable и **не вызывать ни одну v2 функцию**, кроме уже
   вызванного `GetApiInfo`.
9. Создать v2 scene. При ошибке — zero handle, partial resources освобождены
   внутри backend.
10. Только после успешного scene create разрешить `RagdollCreate` и
    `SceneStep`.

`GetApiInfo` не является «доверенным» вызовом: EXE проверяет `structSize`,
`magic`, major/minor и capabilities. DLL, объявившая неподдерживаемую
версию, не получает ни одного последующего вызова.

#### 5.3.3. GetProcAddress: точное поведение

| Ситуация | Detection | Действие | Запрещено |
|---|---|---|---|
| v2 EXE + v1 DLL | `OgsrPhysX2GetApiInfo` == null | v2 unavailable; log; v1 single, если `-physx_ragdoll` и все v1 exports есть; иначе ODE | вызывать любой `OgsrPhysX2*`; cast v1 symbol |
| v1 EXE + v2 DLL | v1 exports присутствуют и совместимы | v1 P2.2A path без изменений; v2 symbols игнорируются | вызывать v2; менять v1 semantics |
| Отсутствует один обязательный v2 export | `GetProcAddress` == null после успешного info | log имя; v2 unavailable; fallback; partial v2 calls запрещены | вызывать уже resolved v2 функции |
| DLL объявляет неподдерживаемую версию | `abiMajor != 2` или `abiMinor < required` | log; v2 unavailable; fallback | вызывать v2 кроме info |
| Нет обязательной capability | `(caps & REQUIRED) != REQUIRED` | log missing bits; v2 unavailable; fallback | partial v2 calls |
| `GetApiInfo` вернул 0/битую структуру | return/size/magic | log; v2 unavailable; fallback | использовать поля структуры |
| v2 scene create: сбой | return 0/zero handle | log; fallback; partial scene не остаётся | сохранять/использовать handle |
| v2 instance create: сбой | return 0/zero handle | только этот NPC ODE; scene/others живы | destroy scene; half instance |
| Оба флага multi | parse flags | log conflict; multi disabled; v1 smoke/ODE | неявное смешение сценариев |

#### 5.3.4. Никаких небезопасных casts

- `GetProcAddress` возвращает `FARPROC`; cast разрешён только к **точному**
  typedef объявленного export, после проверки имени и версии.
- Запрещено cast v1 function pointer к v2 typedef и наоборот.
- Запрещено вызывать symbol через typedef с другой сигнатурой.
- Запрещено reinterpret_cast v1 `void*` handle в v2 handle и наоборот.
- Перед каждым вызовом function pointer проверяется на null; «попробовать и
  посмотреть» запрещено.
- v1 и v2 handles хранятся в разных полях game state; одновременно ненулевыми
  быть не могут.

#### 5.3.5. v1 → v2 mapping

Полные v1 signatures — в §1.4; в таблице они сокращены, но не изменены.
v1 `RuntimeCreate` покрывает scene и первый instance; в v2 это две
операции: `SceneCreate` + `RagdollCreate`.

#### 5.3.6. Ownership при частичном сбое

- `SceneCreate` — transaction: foundation → physics → extensions → dispatcher
  → scene → materials. При любом сбое release в обратном порядке; вызывающий
  получает zero handle и не владеет ничем.
- `RagdollCreate` — transaction: validate → slot reservation → actors →
  shapes → joints → filter data → contact tag → registry publish. При сбое
  release только instance resources, снять tag, освободить slot (generation
  увеличивается, handle не выдаётся); scene и другие instances живы.
- `SceneAddStaticFragment`/`SceneSetStaticMesh` — transaction: cook/validate
  new → attach new → only then release old. При сбое old остаётся активным.
- `SceneDestroy` — освобождает все оставшиеся instances (defensive), static,
  contact registry, scene, dispatcher, materials, extensions, physics,
  foundation; инвалидирует handles. Stale/invalid → 0 + error, no-op.
- Если `SceneCreate` успешен, но caller потерял handle без `SceneDestroy`, это
  leak; backend не имеет глобального «last scene» и не может его reclaim.
- Caller владеет scene handle после успеха; instance handle — после успеха
  `RagdollCreate`; оба обнуляются после destroy.

#### 5.3.7. Обязательные negative tests P3.1

1. v2 EXE + v1 DLL: `GetApiInfo` missing; v2 не вызывается; v1 single/ODE
   fallback; лог.
2. v1 EXE + v2 DLL: все v1 exports сохранены; P2.2A single path проходит.
3. Отсутствует один обязательный v2 export (parameterized по каждому):
   negotiation fail; ни один v2 create/step не вызван; fallback.
4. DLL объявляет `abiMajor != 2` или `abiMinor < required`: v2 unavailable;
   fallback.
5. DLL не объявляет обязательную capability: v2 unavailable; лог missing
   bits.
6. Частичная инициализация: сбой на foundation/physics/scene/material/
   instance actor/shape/joint; проверить отсутствие leaks и zero handles.
7. Оба флага `-physx_multi_instances` и `-physx_ragdoll_multi`: conflict log;
   multi disabled; smoke/ODE path.
8. v1/v2 handle mixing: v2 API с v1 handle и v1 API с v2 handle; отказ без
   разыменования.
9. Stale handle после `SceneDestroy`/`SceneCreate` и после reuse slot.
10. `GetApiInfo` с маленьким/большим `structSize`; DLL не пишет за границу.
11. Capability объявлена, но optional export отсутствует; negotiation
    политика (fail или optional ignore) проверена.

## 6. Handle and resource ownership

### 6.1. Resource table

| Resource | Owner | Lifetime | Cleanup |
|---|---|---|---|
| `PxFoundation`/`PxPhysics`/`PxScene`/dispatcher | scene | level | `SceneDestroy` |
| materials/floor | scene | level | `SceneDestroy` |
| static mesh/fragments | scene | level (no runtime eviction в P3.1) | `SceneDestroy` |
| contact collector/tags/registry | scene | level | per-instance cleanup + `SceneDestroy` |
| collisionInstanceId allocator | scene | level | `SceneDestroy` |
| ragdoll actors/joints | instance | NPC death → destroy | `RagdollDestroy` |
| pose/diagnostics/filter data | instance | same | `RagdollDestroy` |
| contact tag (`PxActor::userData`) | scene, per instance | instance | clear before actor release |
| bone callbacks/slots | game/adapter | instance | reset before `RagdollDestroy` |
| `OgsrPhysX2RagdollHandle` | `CCharacterPhysicsSupport`/state | NPC | zero after destroy |
| `OgsrPhysX2SceneHandle` | level runtime | level | zero after `SceneDestroy` |
| v1 `OgsrPhysXRuntimeHandle` | v1 path only | level | v1 `RuntimeDestroy` |

### 6.2. Generation, reuse and exhaustion (F4)

- Registry: `sceneSlots[4]`, `instanceSlots[64]` (initial; config may reduce/
  increase up to measured budget). Каждый slot хранит `generation`, `alive`,
  `collisionInstanceId`, backend pointer/owner.
- `SceneCreate`: найти free slot; `generation = generation + 1`; если
  результат 0 или slot retired — не использовать; handle = slot+generation.
- `SceneDestroy`: `generation = generation + 1`; пометить free; все ragdoll
  handles с этим `sceneSlot/sceneGeneration` становятся stale.
- `RagdollCreate`: free slot → `generation = generation + 1`; handle =
  scene fields + instance fields; collision ID выделяется отдельно.
- `RagdollDestroy`: `generation = generation + 1`; free; collision ID
  retire; повторный destroy — stale error/no-op.
- `IsAlive`: проверяет scene slot/gen, instance slot/gen, alive flag; только
  потом backend pointer.
- Stale handle никогда не разыменовывает память; registry lookup только по
  slot+generation.
- Generation exhaustion: если `generation == UINT32_MAX` и slot освобождён,
  slot **retired**; не wrap. Если free slots нет — create возвращает ошибку
  `"instance slot generation exhausted"`; NPC уходит в ODE. Для scene —
  `"scene slot generation exhausted"`; все NPC ODE.
- Collision ID exhaustion: если `nextCollisionInstanceId == UINT32_MAX`,
  `RagdollCreate` возвращает ошибку `"collision instance id exhausted"`;
  scene и другие instances живы; ID 0 никогда не выдаётся.

Примеры lifecycle:

1. **Create A → destroy A → create B в том же slot.**
   A = `(scene 0/gen1, instance 0/gen1, collisionId 1)`. Destroy A →
   instance gen 2, collisionId 1 retired. Create B → instance gen 3,
   collisionId 2. Stale A (gen1) не может изменить B (gen3).
2. **Stale A пытается изменить B.**
   `RagdollApplyImpulse(A)`/`GetPose(A)`/`Destroy(A)` → 0 + error
   `"stale ragdoll handle"`; B не затронут; PhysX pointers не читаются.
3. **SceneDestroy → SceneCreate использует тот же scene slot.**
   Scene gen 1 → destroy gen 2 → create gen 3. Старый ragdoll handle имеет
   `sceneGeneration=1`; новый scene gen=3; `IsAlive` false.
4. **Старый ragdoll handle после новой scene.**
   `RagdollDestroy(old)` → stale error; новый scene/instances не затронуты;
   collision ID старого retired и не совпадает с новыми.
5. **Generation near-wrap.**
   Slot gen `0xFFFFFFFE`; destroy → `0xFFFFFFFF`; create не делает wrap в 0,
   а retire slot и ищет другой free slot. Если free slot нет — create fail.
6. **Collision ID exhaustion.**
   `nextCollisionInstanceId == 0xFFFFFFFF`; create fail с диагностикой;
   существующие instances продолжают работать; scene не разрушается.
7. **Double destroy.**
   Первый destroy → 1; второй с тем же handle → 0 + `"stale ragdoll handle"`;
   новый объект на том же slot не удаляется.

### 6.3. Double ownership and v1/v2 path exclusivity

- Один body — один solver: `m_owner` (`ownerNone/ownerODE/ownerPhysX`) в
  `CCharacterPhysicsSupport`; PhysX instance создаётся только при
  `m_owner==ownerNone` и отсутствии ODE shell (`CPS.cpp:1272`).
- `RagdollCreate` не должен создавать ODE shell; `CreateShell` не вызывается,
  пока PhysX instance жив.
- `RagdollDestroy` только для своего handle; `SceneDestroy` только на уровне.
- `OgsrPhysXRagdollState` хранит v2 handle; после destroy state удаляется,
  `m_physx_ragdoll=nullptr`.
- v1 `g_ragdoll_handle`/`g_ragdoll_active` не используются в v2 path; они
  остаются только для v1 P2.2A. v2 state не пишет в эти globals.
- v1 runtime и v2 scene никогда не активны одновременно; переход — только
  через полный teardown (см. §7.3, §9).

### 6.4. Collision identity (F4)

- `collisionInstanceId` — отдельный `uint32_t`, ненулевой, уникальный среди
  живых instances одной scene.
- Выделяется монотонно из scene counter; при destroy **retire**, не
  возвращается в free list. Это исключает повтор identity для stale contact
  tags/filter data.
- 0 зарезервирован для static geometry и non-ragdoll actors.
- Public handle и collision ID не смешиваются: filter shader видит только
  collision ID; game/ABI видит только public handle.
- Collision ID не сериализуется в save; при загрузке выделяется заново.
- Contact tag содержит `collisionInstanceId` + instance slot/generation для
  диагностики; tag не является public handle.

### 6.5. Partial failure ownership

| Сбой | Что уже создано | Что делает backend | Что получает caller |
|---|---|---|---|
| `SceneCreate`: foundation | ничего | release | zero handle |
| `SceneCreate`: physics/extensions | foundation | release в обратном порядке | zero handle |
| `SceneCreate`: dispatcher/scene/materials | предыдущие | release всех partial | zero handle |
| `RagdollCreate`: actors | slot reservation | release actors, free slot, gen++ | zero handle; scene жив |
| `RagdollCreate`: shapes/joints | actors | release joints/actors, clear tags | zero handle; scene жив |
| `RagdollCreate`: filter/tag/registry | actors/joints | clear userData/tags, release | zero handle; scene жив |
| `AddStaticFragment`: cook/validate | ничего | release temp | old fragment активен |
| `AddStaticFragment`: attach new | new actor | release old, keep new | success |
| `AddStaticFragment`: release old fails | new+old | log; retain old до unload | success + warning |
| `SceneDestroy` stale/invalid | — | no-op | 0 + error |

## 7. Scene lifecycle and fixed-step

### 7.1. Порядок уровня (F5)

1. Level load → выбрать path:
   - `-physx_multi_instances` + успешная v2 negotiation → `SceneCreate`;
   - иначе `-physx_ragdoll` + полный v1 export set → v1 runtime;
   - иначе ODE.
2. v2: `SceneCreate` → `SceneSetStaticMesh`/`SceneAddStaticFragment` →
   включить активацию NPC. Static geometry загружается до первого ragdoll.
3. NPC death → capture → `RagdollCreate(scene, definition, config, &handle)`.
   Commit ownership только после успеха.
4. Каждый frame: `CLevel::OnFrame` → `OgsrPhysXRuntimeOnFrame`
   (`Level.cpp:399-404`) → `SceneStep(scene, Device.fTimeDelta, frameId,
   &result)` **один раз**, до `Objects.Update`.
5. `inherited::OnFrame()` → `IGame_Level::OnFrame` → `Objects.Update(false)`
   (`IGame_Level.cpp:123-129`) → `CCharacterPhysicsSupport::in_UpdateCL`
   (`CPS.cpp:630-641`) → `UpdatePhysXRagdoll` → `RagdollGetPose(handle)` →
   bone publication. Шага здесь нет.
6. NPC release → reset bone callbacks → `RagdollDestroy(handle)` → state
   удаляется, handle zero.
7. Level unload → strict teardown (§7.3) → `SceneDestroy` → game references
   zero.

Frame timeline:

| Фаза | Вызов | Владелец | Правило |
|---|---|---|---|
| Physics phase | `OgsrPhysXRuntimeOnFrame` → `SceneStep` | scene | один шаг на frameId; до `Objects.Update` |
| Game update | `Objects.Update` | game | не вызывает `SceneStep` |
| Pose publication | `in_UpdateCL` → `UpdatePhysXRagdoll` | adapter/state | только read/publish; после step |
| Render | renderer | renderer | не вызывает PhysX |
| Teardown | `SceneDestroy` | game/backend | вне simulate/fetch |

### 7.2. Stepping contract

- Владелец шага — scene, не NPC. `SceneStep` вызывает `simulate(0.01)` и
  `fetchResults(true)` ровно один раз на fixed step.
- `frameId` — монотонный uint64, один на `CLevel::OnFrame`, одинаковый для
  всех NPC в этом frame.
- Идемпотентность: если `SceneStep` вызван повторно с тем же `frameId`,
  вернуть cached `OgsrPhysX2StepResult`, не вызывать `simulate/fetch`.
- `frameId < lastFrameId` — ошибка `"non-monotonic frame id"`; новый scene
  начинает с 0.
- Pause: `Device.Paused()`/`delta<=0` → 0 steps; accumulator reset, чтобы
  после resume не было catch-up.
- Time factor: `Device.fTimeDelta` уже масштабирован; не умножать повторно.
- Accumulator (сохраняет текущий P2 clamp `fixed*maxSubsteps*2` из
  `world.cpp:1234-1254`; изменение clamp — только по измерениям):
  ```text
  accumulator += min(delta, 0.25)
  maxAccumulator = fixedTimestep * maxSubsteps * 2.0
  if accumulator > maxAccumulator:
      dropped += accumulator - maxAccumulator
      accumulator = maxAccumulator
  while accumulator >= fixedTimestep and steps < maxSubsteps:
      simulate/fetch
      accumulator -= fixedTimestep
      steps++
  if accumulator >= fixedTimestep:
      keep = fmod(accumulator, fixedTimestep)
      dropped += accumulator - keep
      accumulator = keep
  ```
  `droppedSteps = floor(dropped / fixedTimestep)`;
  `droppedSeconds = dropped`.
- 30 FPS (33 ms) → 3 steps; 60 FPS (16.7 ms) → 1; 120 FPS (8.3 ms) → 0/1;
  большой delta → не более `maxSubsteps`, остаток **dropped**, не
  накапливается.
- Dropped time — намеренная защита от spiral of death; счётчик доступен в
  `OgsrPhysX2StepResult` и diagnostics. Если dropped p95 превышает бюджет,
  это сигнал для performance-тюнинга, а не для изменения fixed step.
- `UpdatePhysXRagdoll` **не** вызывает step; только read/publish.
- Фиксированные 0.01 с, solver 16/4, damping 0.05/0.2 не меняются.
- `SceneStep` при `acceptingWork=false` → 0 + `"scene is shutting down"`.
- Ошибка `fetchResults` → scene failed; дальнейшие `SceneStep` → 0; game
  выполняет teardown и fallback (§9).

### 7.3. Teardown order (F5)

Строгий порядок; нарушение — архитектурная ошибка.

1. **Прекратить новые scene steps и операции создания.** Scene
   `acceptingWork=false`; `SceneStep`, `RagdollCreate`, static updates
   возвращают ошибку.
2. **Дождаться завершения `simulate/fetchResults`.** Teardown только вне
   callback/step; при worker threads — `fetchResults(true)` уже завершён;
   backend assert `!inSimulate`.
3. **Запретить публикацию новых bone poses.** Game выставляет
   `publishing=false` для всех NPC; `UpdatePhysXRagdoll` — no-op.
4. **Освободить OGSR bone callbacks, пока `IKinematics` и instance state
   ещё валидны.** Game layer: reset callback params/slots, очистить
   `OgsrPhysXRagdollState::slots`; backend не трогает `IKinematics`.
5. **Освободить instance ownership/actors/joints.** `RagdollDestroy` для
   каждого; backend снимает `PxActor::userData`, удаляет contact tags,
   release joints/actors, retire collision ID, gen++.
6. **Освободить static geometry и contact registry.** Scene release
   fragments/meshes, collector map, instance registry; handles invalid.
7. **Уничтожить PhysX scene, dispatcher, physics и foundation.** В обратном
   порядке создания; release extensions/materials; `PxCloseExtensions`
   после последнего physics.
8. **Инвалидировать scene handles и обнулить игровые references.**
   `SceneDestroy` gen++; `g_scene2 = {}`; `g_ragdoll_handle = nullptr`;
   `m_physx_ragdoll = nullptr`; `m_owner = ownerNone`.

Разделение ответственности:

- **Game layer:** остановить публикацию, снять bone callbacks, обнулить
  references, выбрать fallback, вызвать `SceneDestroy`.
- **Backend:** PhysX resources, registry, contact tags, idempotent
  `SceneDestroy`/`RagdollDestroy`; не вызывает game callbacks после
  teardown.
- **Adapter:** mapping bone↔body; после снятия callbacks не обращается к
  уничтоженному state.

Сценарии тестирования:

- Два NPC у границы разных static fragments.
- Удаление одного NPC не удаляет collision для второго.
- Отказ cook/replacement; old geometry продолжает работать.
- Level unload с активными bone callbacks.
- Повторное удаление NPC (stale destroy).
- `SceneDestroy` при нескольких активных instances.
- Reload и попытка использовать старый handle.
- Teardown при `acceptingWork=false` и повторном `SceneStep`.

## 8. Collision filtering and static mesh

### 8.1. Exact collision filtering contract (F3)

`PxFilterData` layout:

```text
word0: group bits
       OGSR_PHYSX2_GROUP_RAGDOLL   = 1 << 0
       OGSR_PHYSX2_GROUP_STATIC    = 1 << 1
       OGSR_PHYSX2_GROUP_ODE_PROXY = 1 << 2  (reserved; not in P3.1 scene)
word1: mask bits (same bit namespace as word0)
word2: collisionInstanceId
       nonzero for every ragdoll shape; 0 for static geometry
word3: flags
       OGSR_PHYSX2_FILTER_RAGDOLL                = 1 << 0
       OGSR_PHYSX2_FILTER_STATIC                 = 1 << 1
       OGSR_PHYSX2_FILTER_DISABLE_SELF_COLLISION = 1 << 2
       bits 3..31 reserved, must be 0
```

- Instance ID **не дублируется** в `word3`; `word3` — только flags.
- `word2` — collision identity, не public handle и не `slot|generation`.
- Static geometry: `word0=STATIC`, `word1=RAGDOLL`, `word2=0`,
  `word3=STATIC`.
- Ragdoll default: `word0=RAGDOLL`, `word1=RAGDOLL|STATIC`, `word2=id`,
  `word3=RAGDOLL | (disableSelfCollision ? DISABLE_SELF_COLLISION : 0)`.
- Symmetric group/mask rule:
  ```c
  ((groupA & maskB) != 0) && ((groupB & maskA) != 0)
  ```
- Decision order:
  1. Validate classification: `(RAGDOLL|STATIC)` must be exactly one flag;
     both/neither → suppress + `invalidFilterPairs++` (fail-safe).
  2. `STATIC` + `STATIC` → suppress (no separate scenario in P3.1).
  3. Both `RAGDOLL`, `word2 != 0`, `word2` equal, and either shape has
     `DISABLE_SELF_COLLISION` → suppress.
  4. Symmetric group/mask rule; fail → suppress.
  5. Allow; if `collectContacts` and at least one ragdoll, set contact pair
     flags; static-static never reaches here.
- Self-collision:
  - same ragdoll, `disableSelfCollision=1` → suppress;
  - same ragdoll, `disableSelfCollision=0` → group/mask check; if pass, allow;
  - different ragdolls → **allow by mask**, even if `word3` flags equal;
  - `word2` equality is the only self identity check.
- Inter-ragdoll collisions default allowed; scene can disable them only via
  group/mask policy, not via `word3` equality.
- Static/ragdoll → allow by mask. Static/static → suppress.
- ODE objects не входят в PhysX scene; прямого coupling нет.
  `ODE_PROXY` зарезервирован, в P3.1 не выставляется.
- Triggers: в P3.1 trigger shapes не создаются. Если trigger shape
  встретился, suppress + counter; отдельная trigger policy — future feature.
- Contact notifications: только при `collectContacts`; pair flags
  `eNOTIFY_TOUCH_FOUND|eNOTIFY_TOUCH_PERSISTS|eNOTIFY_TOUCH_LOST|
  eNOTIFY_CONTACT_POINTS`; static-static — нет; trigger — отдельно.

Ожидаемые решения:

| Пара | Ожидаемое поведение |
|---|---|
| Один NPC, self disabled | Suppress |
| Один NPC, self enabled | Проверка group/mask; при pass — allow |
| Два разных PhysX NPC | Разрешить по group/mask |
| PhysX NPC и static level | Разрешить по group/mask |
| Две static shapes | Suppress для обычного collision |
| PhysX и ODE | Нет прямого coupling; ODE вне scene |
| Trigger shape | В P3.1 не создаётся; при встрече suppress + counter |

Filter data lifetime и изменения:

- Scene filter policy (`PxSceneDesc.filterShaderData`) — immutable constant
  block на время жизни scene; shader не читает process-global mutable state.
  Глобальные `g_suppressRagdollSelfCollision`/`g_collectRagdollContacts`
  удаляются.
- Per-shape filter data задаётся при создании shape и неизменен в P3.1,
  кроме явного runtime-изменения (future): обновить `word0/word1/word3` у
  всех shapes instance, вызвать `PxShape::setSimulationFilterData`, затем
  `PxScene::resetFiltering(actor)` для каждого actor. Только вне
  `simulate/fetch`. P3.1 recommended: `disableSelfCollision`/group/mask —
  create-time only; runtime change не обещается.
- `resetFiltering` обязателен после изменения filter data живого actor и
  после замены static actor, если затронуты пары; без него broadphase/
  narrowphase может сохранить старое решение.
- Contact attribution: `PxActor::userData` указывает на scene-owned
  `ContactTag { collisionInstanceId, instanceSlot, instanceGeneration }`;
  static actor — null/0. `onContact` читает tags обоих actors, атрибутирует
  событие каждому ragdoll (для ragdoll-ragdoll — обоим); missing tag →
  `unattributedContacts++`, без падения. Не хранить raw `OgsrPhysXRagdollState*`
  в userData.
- Cleanup: перед release actor — `userData=nullptr`, удалить tag из
  registry/map; после `SceneDestroy` registry пуст; stale tag не может
  сослаться на новый instance, потому что collision ID не reuse.
- Per-instance diagnostics: contactCount/found/persist/lost/activePairs/
  totalImpulse/maxPenetration; для пары двух ragdoll каждый получает pair
  impulse (это не глобальное двойное суммирование; scene counters отдельно).
- Test not only count: два NPC, перекрытие/контакт, импульс A → B должен
  получить velocity/position change и contact impulse > 0. Отдельно:
  self-collision off не подавляет A-B; static collision работает; две static
  shapes не генерируют пару; stale tag после destroy не атрибутируется.

### 8.2. Static fragments and safe replacement (F5)

P3.1 baseline:

- **No runtime eviction** загруженных static fragments до level unload.
  Загрузить level mesh/фрагменты один раз, измерить память; если бюджет
  укладывается — не evict.
- `SceneAddStaticFragment(scene, key, mesh)` добавляет/заменяет фрагмент по
  64-bit key; `key` — grid cell или стабильный region id. Дубликат key —
  transactional replacement.
- `SceneSetStaticMesh` — whole-level mesh; вызывается на level load, не на
  каждого NPC. Per-NPC `SetStaticFragment` больше не используется.
- Старый 48×24×48 box остаётся diagnostic fallback для v1/P2.2A, но не
  production static geometry.

Future eviction (если измеренный бюджет потребует):

- Union world-space bounds всех live ragdoll actors, расширенный на:
  - max linear velocity * fixedTimestep * safety factor (движение между
    steps);
  - contact/swept bounds: shape bounds + contactOffset + restOffset + margin;
  - запас у границ ячеек: удерживать соседние фрагменты, если expanded AABB
    пересекает границу cell + margin.
- Фрагмент нельзя release, пока его bounds пересекает expanded AABB хотя бы
  одного live instance, или пока есть pending contact pair/actor reference.
  Refcount per fragment; release только при refcount==0.
- Eviction только вне `simulate/fetch`; после eviction/добавления при
  необходимости `resetFiltering` затронутых ragdoll actors.
- Eviction по центру NPC запрещён.

Transactional replacement:

1. Подготовить/cook новую геометрию в temp `PxTriangleMesh`/`PxShape`/
   `PxRigidStatic`, не attached к scene.
2. Проверить mesh: non-empty, finite vertices, index range, triangle cap,
   cooking success.
3. Убедиться, что scene не в `simulate/fetch`; replacement только на frame
   boundary.
4. Attach new actor/shape к scene; при необходимости `resetFiltering`
   затронутых ragdoll actors.
5. Только после подтверждённого успеха release old actor/mesh.

При ошибке на шагах 1–3 old geometry остаётся активной; temp resources
release; возвращается ошибка. При ошибке release old (шаг 5) new остаётся
активным, old можно retain до level unload; log warning, no crash. При
ошибке attach new (шаг 4) old не трогается.

### 8.3. Whole-level static mesh

- `SceneSetStaticMesh` — тот же transactional contract; active instances не
  теряют collision.
- Replacement только вне `simulate/fetch`; при замене whole-level mesh
  желательно делать это до создания instances; если после — temporary
  overlap old/new не допускать, release old только после attach new.
- Ошибка cook/attach → old mesh продолжает работать; level не падает.
- Память static geometry входит в performance matrix; решение об eviction
  принимается после baseline, не до него.

### 8.4. ODE objects

- ODE objects не участвуют в PhysX scene до отдельного coupling feature.
- `ODE_PROXY` group зарезервирован, но не выставляется в P3.1.
- Никаких proxy shapes, kinematic bridges или contact forwarding в P3.1.
- Будущий coupling — отдельный ADR с тестами импульсов/ownership.

## 9. ODE fallback and failure recovery

| Ситуация | Detection | Поведение | Scene/other instances |
|---|---|---|---|
| v2 unavailable (missing export/version/caps) | negotiation | log; v1 single если `-physx_ragdoll` и v1 exports complete; иначе ODE | v2 scene не создаётся |
| Scene create failure | `SceneCreate` 0/zero | все NPC ODE; v2 runtime не активируется | partial scene освобождён |
| Scene step failure | `SceneStep` 0 / `fetchResults` fail | scene failed; остановить v2; teardown; новые смерти — ODE; existing instances release без auto-ODE | scene destroyed; others invalid |
| Instance create failure | `RagdollCreate` 0/zero | только этот NPC ODE; scene/others живы | scene remains |
| Instance runtime failure (pose/impulse) | API 0 | log; если instance corrupted — `RagdollDestroy`; другие живы; auto-ODE из last pose не обещается | scene remains |
| NPC destruction | release | `RagdollDestroy`; scene жив | others unaffected |
| Visual replacement | `OnBeforeVisualChange`/`in_ChangeVisual` | release instance до смены visual; ODE shell не создаётся автоматически | scene remains |
| Level unload | unload | strict teardown; `SceneDestroy` | all invalid |
| Handle reuse | stale | generation++/stale rejected | new object untouched |
| Allocation/joint/shape failure | create fail | instance rollback; ODE for NPC; no scene destroy | scene remains |
| Both multi flags | parse | conflict log; multi disabled; v1 smoke/ODE | no v2 scene |

- **До commit:** rollback безопасен — удалить instance, temp shell уже удалён,
  `m_owner=ownerNone`, ODE `CreateShell`.
- **После commit:** обратного перехода в animation нет. При ошибке publish —
  log + keep instance. При потере instance — release + **не** автоматически
  создавать ODE shell из последней позы: это отдельная recovery feature,
  требующая тестов на double ownership, pose validity и gameplay. P3.1
  может оставить corpse/frozen visual или скрыть его; другие instances не
  трогать.
- `SceneDestroy` никогда не вызывается из `ReleasePhysXRagdoll` одного NPC.
- v2 → v1 fallback: только после полного `SceneDestroy` и teardown; v1 runtime
  создаётся заново; handles не смешиваются.
- v2 → ODE fallback: новые смерти идут в ODE; уже созданные PhysX instances
  либо продолжают жить (instance failure — только один), либо release при
  scene failure; auto-ODE не обещается.

## 10. Save/load limitations

- Сейчас `in_NetSave` (`CPS.cpp:373`) пишет только `CPHSkeleton::SaveNetState`;
  PhysX state не сериализуется.
- `net_SaveRelevant` (`base_monster_net.cpp:16`, `ai_stalker.cpp:624`) —
  `PPhysicsShell()!=nullptr`; PhysX path держит `m_pPhysicsShell=nullptr`
  (`CPS.cpp:93`), поэтому мёртвый PhysX NPC может не попасть в save.
- `in_Load` (`CPS.cpp:159-167`) не восстанавливает PhysX.
- Контракт P3.1: save/load **не реализуется**. v2 handles/generations и
  collisionInstanceId не сериализуются.
- Для будущего:
  - old saves без PhysX chunk → ODE;
  - new save chunk: solver tag + ABI major/minor + scene version + body
    pose/velocity + stepIndex + seed;
  - load: PhysX chunk + available scene → recreate instance; иначе ODE shell
    из pose; no partial PhysX;
  - collision ID выделяется заново; stale IDs не восстанавливаются;
  - network: PhysX ragdoll не реплицируется; каждый клиент симулирует
    локально; `in_NetDestroy` освобождает instance.
- Не обещать save/load без отдельного gameplay-теста (P3.2+).

## 11. Performance measurement plan

### 11.1. Baseline P2.2A

Один ragdoll, 11 bodies, 2 worker'а, static fragment 3127/3048 tris:
`avg_ms=0.09–0.33`, `max_ms=0.25–1.9` на кадр
(`artifacts/p22a-full-closure/physx-8ns.log`, `physx-40ns.log`). Это
baseline одного экземпляра, не multi.

### 11.2. Стенд

- **1/2/4/8 одновременно активных PhysX ragdoll** в одной scene, одинаковые
  11/10, фиксированные spawn points. Не последовательное использование
  одного слота.
- 600 fixed steps; 30/60/120 FPS; pause/time factor; create/destroy одного
  при живых остальных; 10 unload/reload.
- Отдельно: create/destroy churn (A/B reuse slot), static fragment boundary,
  inter-ragdoll contact, dropped time.
- Метрики:
  - `SceneStep` total ms, simulate vs fetch, avg/p50/p95/max;
  - pose readback per instance, bone callback ms (47 bones each);
  - static mesh bytes/triangles, per-instance actors/shapes/joints/pose;
  - create/destroy latency;
  - contacts/active bodies/awake per instance;
  - `TrackingAllocator` bytes (расширить `outstanding()` до bytes);
  - droppedSteps/droppedSeconds;
  - leaks после reload (`outstanding` возвращается к baseline).
- Сначала baseline, затем бюджеты. Не назначать бюджет до измерений.
- `workerThreads` — параметр v2 config для будущей реализации. Текущий P2
  backend hardcode 2 (`world.cpp:401`); P3.1 не утверждает, что значение
  уже honored. `CAP_CONFIGURABLE_WORKERS` optional; если capability нет,
  backend может игнорировать значение с логом.
- P3.1 baseline: no runtime eviction; измерить static memory, чтобы решить,
  нужна ли eviction позже.
- Acceptance performance: 2 NPC без регресса v1 single; 4/8 — target после
  baseline; p95 frame cost и dropped time фиксируются, бюджеты назначаются
  отдельно.

## 13. План минимальной реализации P3.1

0. **Freeze v1 ABI:** зафиксировать 12 ragdoll exports + generic runtime
   exports; добавить compile-time проверки сигнатур; v2 header с новыми
   именами. Не менять v1 semantics.
1. **Backend split:** `PhysXRagdollScene` (foundation/physics/scene/
   dispatcher/materials/static/contact/step/registry) +
   `PhysXRagdollInstance` (actors/joints/pose/filter/diagnostics).
   Сохранить v1 single wrapper для P2.2A тестов.
2. **v2 registry:** full 32-bit scene/instance generations; collision ID
   allocator; stale validation; transactional create/destroy; `IsAlive`.
3. **ABI loader/negotiation:** `OgsrPhysX2GetApiInfo`; resolve mandatory
   exports; `-physx_multi_instances`; v1/v2 path selection; negative tests.
4. **Game integration:** `g_scene2` на уровень; `OgsrPhysXRagdollState`
   хранит v2 handle; убрать single gate только под v2 flag; v1 path
   untouched; `UpdatePhysXRagdoll` только publish; `ReleasePhysXRagdoll`
   destroy instance.
5. **Static:** scene-level mesh/fragment registry; no runtime eviction;
   transactional replacement; `SceneAddStaticFragment`; no per-NPC replace.
6. **Filter:** word0/1 group/mask; word2 collision ID; word3 flags; scene
   constant block; contact tags; impulse test; remove globals.
7. **Lifecycle:** `SceneStep` frameId idempotence; dropped time; ordering

   destroy.
8. **Tests:** 2 NPC (11/10 each), independent create/destroy, one scene step,
   self/other collision + impulse transfer, stale handle, unload/reload,
   ODE fallback, static boundary, ABI negative matrix, 1/2/4/8 performance.
9. **Feature flag:** `-physx_multi_instances` default OFF; v1 single remains
   fallback; `-physx_ragdoll_multi` only smoke; both flags conflict reject.
10. **Docs/status:** update roadmap; independent re-review; no PASS until
    review.

Не начинать P3.1 до утверждения этого ADR независимым reviewer.

## 17. Open architectural questions

Точный список; вопросы не блокируют R1 ADR, но должны быть закрыты до
соответствующих P3.1 шагов.

1. **Eligibility scope v2.** `-physx_multi_instances` включает всех
   подходящих stalker'ов или только target list? Рекомендация: все
   подходящие; требует gameplay sign-off. Блокирует P3.1 game integration.
2. **Runtime filter changes.** P3.1 делает `disableSelfCollision`/group/mask
   create-time only или разрешает live update с `resetFiltering`?
   Рекомендация: create-time only; live update — future. Блокирует только
   если product требует live toggle.
3. **Static fragment granularity/budget.** Grid cell size, max triangles,
   memory budget; P3.1 no eviction. Блокирует future eviction, не P3.1
   baseline.
4. **Contact volume.** Сколько contact events дают 4/8 ragdoll; нужна ли
   фильтрация pair events. Блокирует performance budget.
5. **`workerThreads` control.** P3.1 оставляет 2 или реально управляет
   dispatcher? Рекомендация: parameter + optional capability; не обещать.
   Блокирует performance tuning.
6. **`SceneDestroy`/`RagdollDestroy` return type.** Предложен `int` с
   диагностикой; финализировать в header review. Блокирует ABI freeze.
7. **Max instances/registry growth.** Initial 64; growable или fixed?
   Блокирует memory budget.
8. **v1/v2 DLL packaging.** v2 DLL обязан сохранять v1 exports; как
   версионируется deployment? Блокирует build/release plan.
9. **Save/load chunk format.** ABI tag, scene version, pose/velocity, seed;
   out of scope P3.1. Блокирует P3.2+.
10. **Post-commit ODE recovery.** Автоматический ODE shell из last pose —
    separate feature; требует тестов double ownership/pose validity.
    Блокирует только future recovery, не P3.1.
11. **`GetApiInfo` structSize policy.** Exact v0 size vs `>=` with forward
    fields; предложено `>= V0_SIZE`, DLL writes bounded. Блокирует header
    review.
