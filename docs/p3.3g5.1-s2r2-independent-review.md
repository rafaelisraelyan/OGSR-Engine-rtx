## 3. Old S2R1 hang explanation independently grounded

**Historical file** `source/s2r1/ogsr_s2r1_harness.cpp` lines 46–47:
```cpp
if (!g_pGameLevel || !g_pGameLevel->bReady)
    return;
```
The `switch (m_phase)` and `case phaseDisconnectWait:` appear **after** this guard (starting ~line 75 and ~129). Thus after `xr_delete(g_pGameLevel)`, `Tick/OnFrame` returns before it can call `Engine.Event.Defer("KERNEL:start")`. That is a **demonstrated test-only state-machine logic bug**.

In S2R2 source, **`if (m_phase == phaseDisconnectWait)` and `TickDisconnectWait()` execute before the null-level guard** (~line 76 vs ~97), and explicitly enqueue next `KERNEL:start` when `!g_pGameLevel`. The old-guard control simulation `G51_S2R2_SIMULATE_OLD_GUARD=1` intentionally returns before queuing, and `logs/s2r2-oldguard-dump5.log` contains `simulating S2R1 early-return guard`, no subsequent `level down` or `queue level start`, though production disconnect/menu completed.

**Dump assessment:** Original 4.6-GB dump was **not included**; its malformed 15 zeroed directory entries are evidenced only by saved header-parser/WinDbg outputs, not independently verified dump bytes. The supplied **new 879,694-byte mini-dump** has a valid `MDMP` directory and module `RSDS` record (age 1). Bundled `logs/s2r2-oldguard-dump5-stacks.txt` shows `xrEngine!CTheoraSurface::DecompressFrame → CMainMenu::OnRender → CRenderDevice::on_idle → message_loop → Run`. This snapshot supports **active main-menu rendering**, not a main-thread PhysX wait. `!analyze -hang` bucket `ntdll!DbgBreakPoint` is from debugger break/snapshot; **not** an independent root-cause indicator of an exception. A single thread snapshot alone cannot rule out every background thread issue, but **source logic + old-guard reproduction + successful fixed controls** strongly establish the actual blocker.

**Causal conclusion:** the historical live-2 “hang” was a missing harness event transition and indefinite menu idle, **not a demonstrated production deadlock**. Do not add speculative fixes to PhysX, `CApplication::OnEvent`, or the menu.
