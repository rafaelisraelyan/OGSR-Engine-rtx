## 2. Gameplay stress matrix — staged acceptance

**Must be real human NPC deaths/ragdoll creation during an active game world**, not just synthetic CTest fixtures or diagnostic callback registration. Preserve same saves, GPU renderer, weather, camera, spawn population, machine and feature flags for A/B vs ODE.

| Stage | Concurrent living/dead NPC interaction | Acceptance evidence |
|---|---|---|
| S1 | 1 human stalker death → PhysX ragdoll | Current animated pose/velocity transfer, correct visual/skeleton, level/static collider contacts, no second ODE shell |
| S2 | 2 human ragdolls | Both simulated, callback and registry counts correct, corpse/loot interactions, unload → zero live bodies and lease refs |
| S3 | 4 ragdolls | Increased cap with **actual source-supported configuration**; different NPC models/factions, contact stability, no duplicated solver |
| S4 | 8 ragdolls | More than one scene/region, corpse persistence and repeated spawn/remove, no UAF or stale callbacks |
| S5 | 16 ragdolls | Frame/physics p50/p95/p99 and peak memory vs ODE baseline, collision correctness, two reload/save/load cycles and clean exit |

If cap is reached or rig/static collision coverage is unsupported: **count and explain ODE fallback**, not a PhysX PASS for that NPC. Consider 32/40 only after 16 is stable and performance budget/scene capacity justify it; 40 is an upper option, not an acceptance minimum.

Capture per NPC: section/visual, rig family, PhysX attempted/succeeded/fallback reason, body/shape/joint counts, active ragdoll peak, ODE shell state, world static tile coverage, renderer, save/reload session, repeated lifecycle and resource lease release. Record callback generation/ownership and avoid stale snapshots across level unload.

**Features explicitly deferred:** PhysX locomotion/controller for living NPCs, AI locomotion, mutants/creatures, actor physics replacement, PhysX GPU/CUDA, cross-solver two-way impulses, global default enable.
