# F4.1 — Implementation Report: полная статическая сцена Jupiter в native DX12

Дата: 2026-11-21. Ветка: `feature/f41-full-static-jupiter` (база `81956aa1a`,
F4.0-B-VSLICE). Merge в `prypiat` не выполнялся, push не выполнялся.

уровня Jupiter** из оригинальных игровых данных, без ручных списков объектов:

## 2. Что именно убрано из обычного runtime

- Жёсткий выбор сектора `129`/`130` и корня `17431`.
- Список визуалов `9,105,106,107` (`fourvisual12::kPlan`) как единственный
  источник геометрии.
- Диагностическая NDC-раскладка 2×2 перед камерой.
- Лимит «пять объектов» (`kSceneCapacity = 64`, `maxInstances = 64`,
  `maxTotalAssetBytes = 4 MiB`).

Диагностический путь M23/J1 сохранён как отдельный opt-in
(`OGSR_DX12_GAME_M23`, `OGSR_DX12_GAME_B1_WORLD`) и в обычном runtime не
участвует. Полную сцену можно выключить `OGSR_DX12_GAME_STATIC_SCENE=0`.

## 3. Архитектурные решения

1. **Геометрия не переупаковывается.** Аудит R4 подтвердил: статика уровня
   уже в мировых координатах, identity world (`r__dsgraph_render.cpp:18`),
   `_NormalItem` без матрицы, вершины в общих пулах `level.geom`
   (`FVisual::Render` → `vBase/vCount`, `iBase/iCount`). Поэтому пулы
   загружаются на GPU как есть, а draw использует поддиапазоны пулов.
   Это и есть переиспользование буферов/инстансинг: одна загрузка на
   уровень, много draw.
2. **Один разбор вместо O(n²).** `xraylevel12::ReadLevelPools` разбирает
   контейнер визуалов и пулы один раз и публикует метаданные (диапазоны,
   раскладки, границы). Прежний `ReadVisual` заново разбирал пулы на каждый
   visual, что для 20880 визуалов неприемлемо.
3. **Штатный обход, без второго загрузчика.** VFS-снапшот
   (`GameDx12J2ABatch_ReadSnapshot`), `levelhierarchy12::Parse`,
   `CollectLeaves`, затем собственный обход достижимости от корней секторов.
4. **Расширение по фактическим данным.** Поддержаны три реально
   встречающиеся раскладки вершин и `MT_PROGRESSIVE`; неподдержанное
   считается и логируется, а не скрывается.
5. **Уровневая загрузка ресурсов.** Всё привязано к `level/session/epoch`;
   при teardown/device reset ресурсы освобождаются, при неизвестном
   завершении — уходят в process-lifetime карантин.

## 4. Найденные по ходу факты (важно для следующих этапов)

- Реальные раскладки вершин (`stride 32`): `Classic` (COLOR@24 +
  TEXCOORD@28) — 1844 визуала; `UvAt24` — 6848. Один input layout
  недостаточен, нужны два PSO.
- `MT_PROGRESSIVE` (789) — крупные патчи рельефа, которые leaf-обход не
  эмитит. Без них карта выглядела «продырявленной»; пиксели в дырах точно
  совпадали с цветом очистки, что доказало отсутствие геометрии, а не
  проблемы culling/alpha.
- Деревья: 3035 `MT_TREE_ST` + 2184 `MT_TREE_PM`. Не поддержаны (нужен
  per-instance `tree_data`), учтены как `skipped_tree_nodes=5219`.
- InfoQueue по умолчанию хранит 1024 сообщения; при 8692 draw очередь
  переполнялась и вердикт становился `UNVERIFIED`. Лимит поднят до 2^18 —
  теперь диагностика полная (`discarded=0`).
- Буферы нельзя создавать в `COPY_DEST` и нельзя переводить барьером так,
  как это делалось: и то, и другое даёт 47 предупреждений Debug Layer.
  После исправления — 0 предупреждений.

## 6. Делегирование Sol/Terra

- Terra (субагент, read-only) — карта R4 traversal: как R4 читает
  `level`/`level.geom`, что секторы/порталы/иерархия не хранят мировых
  матриц для статики, где identity world. Sol проверил выводы по коду и
  использовал их как основание архитектуры (пулы как есть).
- Terra — аудит форматов: единственная поддержанная декларация, лимиты,
  DDS/THM, где теряются текстуры. Sol расширил раскладки/DDS/материалы по
  фактическим данным и реализовал GPU-путь.
- Terra — инвентарь ограничений рантайма (сектор 129/130, 5 визуалов,
  ёмкости, env-флаги, состояние моста). Sol снял ручной отбор.
- Terra — восстановление процедуры сборки/запуска (команда MSBuild, аргументы,
  состав run dir, fsgame, захват кадров). Sol автоматизировал это в
  `run-f41.ps1` и `summarize-f41.ps1`.
- Итоговые runtime-проверки, GPU-код, интеграция и разбор артефактов
  выполнены основным агентом.

## 7. Ограничения (не выдаются за готовое)

- Деревья: `MT_TREE_ST` (3015) рисуется по `OGF_TREEDEF2`; `MT_TREE_PM`
  (2184) не рисуется — нужен instanced PM-путь. Ветровая анимация
  (`tree_data` / instanced vertex attributes) не реализована.
- Нет скайбокса/атмосферы: небо — цвет очистки.
- Нет теней, PBR, RTX, динамических объектов, HUD, эффектов.
- Нет порталов/HOM и LOD по расстоянию: только frustum culling; у
  `MT_PROGRESSIVE` берётся окно 0, у `MT_LOD` — первый уровень.
- Прозрачные blended-материалы рисуются как opaque/cutout (тёмные пятна
  воды/грязи на аэро-кадре — это они, не «дыры»).
- Загрузка уровня блокирует owner thread (снапшот + upload ≈ 0.8–1.0 с на
  Jupiter при тёплом кэше).
- `RunFullStaticScene` не распараллелен: один command list на кадр.

## 8. Проверки, которые НЕ подтверждены

- Полный цикл `vid_restart` на полной сцене (проверялся только F4.0-B).
- Смена уровня Jupiter → Zaton → Jupiter внутри native DX12 (в этом этапе
  проверены только загрузка и один переход teardown).
- Device loss на полной сцене.
- DX11/R4 feature-on вариант: регрессия выполнена на feature-off сборке
  (чистый R4). Feature-on R4 не перепроверялся в этом этапе.
- Журнал прошлых сбоев: access violation после DX12 shutdown, Lua fixture,
  ранний startup AV — в этих прогонах **не воспроизводились**, но и не
  объявляются исправленными: причина не установлена.
