**Статус: PASS по code/runtime gates; PARTIAL только по сравнительному видео.**

## 2. ODE KillHit order

### Исправление

`CCharacterPhysicsSupport::KillHit()` теперь выбирает порядок по
`OgsrPhysXRagdollRequested()`:

- PhysX requested: death motion → PhysX attempt → ODE fallback `CreateShell()`;
- PhysX not requested: **оригинальный ODE порядок** `CreateShell()` → death
  motion.

Это работает и в feature-off сборке, и в PhysX-скомпилированной сборке без
`-physx_ragdoll`. `-physx_ragdoll_ode_smoke <target>` — отдельный
диагностический флаг, который не включает PhysX runtime, но прогоняет
smoke-смерть через ODE.

### Evidence

PhysX-compiled build, без `-physx_ragdoll`:

```text
ph_ragdoll_smoke: lethal hit ... ode_only=1
ph_ragdoll_smoke: ODE KillHit uses original order (CreateShell first)
ph_ragdoll_smoke: ODE-only death check target=1 shell=1 physx_instance=0
```

Feature-off DX11 runtime:

```text
ode_death_smoke: lethal hit target=[sim_default_stalker_26525 / sim_default_stalker_2] id=6525
ode_death_smoke: check target=1 shell=1 alive=0
```

Логи: `artifacts/runtime-gate/xray_gr_26-10-26_02-20-19.log`,
`.../xray_gr_26-10-26_03-06-13.log` (финальный ODE order),
`.../xray_gr_26-10-26_02-54-27.log` (feature-off).

## 3. Two live NPCs / ODE fallback / slot reuse

Диагностический запуск:

```text
-physx_ragdoll sim_default_stalker_2 -physx_ragdoll_smoke -physx_ragdoll_multi
```

Сценарий:

1. Первый NPC убит → PhysX ragdoll создан.
2. Через `g_cl_Spawn` добавлены два NPC.
3. Второй NPC убит при активном PhysX instance → ODE fallback.
4. Первый NPC уничтожен → PhysX instance released.
5. Третий NPC убит после освобождения → PhysX slot создан заново.

Лог:

```text
multi spawned two extra stalkers
multi second hit id=6538 physx_instance=1
multi destroying first PhysX NPC id=6525
PhysX ragdoll instance released
multi third hit id=12295 physx_instance_before=0
PhysX ragdoll created bodies=11 joints=10 bones=47 ...
multi result second=1 shell=1 third=1 shell=0 physx_instance=1
multi destroying third PhysX NPC id=12295
PhysX ragdoll instance released
```

Второй NPC остался на ODE (`shell=1`), третий — PhysX (`shell=0`,
`physx_instance=1`). Лог: `xray_gr_26-10-26_02-24-26.log`.

## 4. Two unload/reload cycles with active ragdoll

Добавлен диагностический флаг `-physx_ragdoll_reload` и сброс smoke-флагов
через `OgsrPhysXRagdollSmokeReset()` на старте уровня. Сброшены `frame`,
`fired`, `listed`, `hitFrame`, `reloadRequested`, `staged`, `stagedFrame`,
multi/visual-флаги.

Лог:

```text
reload gate requesting level disconnect with active ragdoll
unloading NPC ragdoll level
ragdoll reload 1/2 requested
reload receiver armed
reloading level
PhysX ragdoll created ...          # после reload 1
reload gate requesting level disconnect with active ragdoll
ragdoll reload 2/2 requested
reload receiver armed
reloading level
PhysX ragdoll created ...          # после reload 2
```

Оба reload завершились; после второго reload PhysX ragdoll снова создан.
После каждого reload в логе снова `tick frame=1`, что подтверждает сброс
process-static smoke-флагов. Третий disconnect уже не армит reload (`2/2`),
игра уходит в unload. Лог: `xray_gr_26-10-26_02-47-37.log`.

## 5. Feature-off DX11 runtime

Сборка:

```text
msbuild Engine.sln /t:XR_3DA /p:Configuration=Release /p:Platform=x64 `
  /p:OgsrDiagnosticRuntimeWorkaround=true /m:1 /nr:false
```

`OgsrDiagnosticRuntimeWorkaround` теперь применяется и без PhysX-флагов; это
нужно только для архивного runtime. Бинарник не содержит `ph_ragdoll`,
`NPC ragdoll`, `ogsr_physx_runtime`, `OGSR_PHYSX_RAGDOLL`.

Runtime загрузился, DXGI/D3D11 renderer и DLSS инициализированы; ODE-смерть
проверена через `-ode_death_smoke sim_default_stalker_2`:
`shell=1`, `alive=0`, без PhysX instance и без crash.
Лог: `xray_gr_26-10-26_02-54-27.log`.
