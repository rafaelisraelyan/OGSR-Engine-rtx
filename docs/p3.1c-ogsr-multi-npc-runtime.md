**P3.1-C-R3:** F3 — `ReconcileSceneDestroyV2` больше не удаляет C++ wrapper,

**P3.1-C-R1:** teardown стал fail-closed: `SceneDestroy`/`RagdollDestroy`

## 0. P3.1-C-R2 — fault-path lifecycle

**F1 (quarantined IKinematics).** `OgsrPhysXRagdollRelease` и
`ReleaseAllV2` после снятия bone callbacks обнуляют `state->kinematics`;
`removeCallbacks` безопасно пропускает null. Игровой visual replacement с
одноразовым fault:

```

! ph_ragdoll: v2 instance release failed npc=6525: fault injection: RagdollDestroy failed; state quarantined

Повторено 3 сессии без crash/UAF.

**F2 (strict ReleaseAllV2).** Результат содержит `remaining` и `handles`.
`shutdown` делает retry, логирует quarantined handles, выполняет
`SceneDestroy` с retry; при success вызывает
`OgsrPhysXRagdollReconcileSceneDestroyV2` — освобождает per-instance lease
refs и удаляет quarantined states. Persistent `RagdollDestroy` fault:

```
! ph_ragdoll: v2 instance release failed npc=6525 ... state quarantined
ph_ragdoll: ReleaseAllV2 complete=0 remaining=2 live=2
! ph_runtime: quarantined instance scene=(0,1) instance=(1,2)
! ph_runtime: quarantined instance scene=(0,1) instance=(0,1)
ph_runtime: v2 teardown state: remaining=2 live=2 lease_refs=3

ph_ragdoll: reconciled 2 quarantined instance(s) after SceneDestroy; live=0
ph_runtime: v2 scene destroyed; lease_refs=0
```

One-shot `SceneDestroy` fault: attempt 1 fail, attempt 2 success,
`lease_refs=1 → 0`. DLL unload guard: при persistent SceneDestroy failure
lease refs остаются, `unload` отклоняется (standalone test).

Env: `OGSR_PHYSX2_FAULT_RAGDOLL_DESTROY[_ONCE]`,
`OGSR_PHYSX2_FAULT_SCENE_DESTROY[_ONCE]`.

## 0.1 P3.1-C-R3 — game-owned state lifetime (F3)

**Дефект F3.** `ReconcileSceneDestroyV2` удалял все quarantined states. В
реальном OGSR порядке `CLevel::net_Stop` вызывает
`OgsrPhysXRuntimeOnLevelUnload()` (→ `shutdown()` → `SceneDestroy` +
reconcile) **до** `remove_objects()`. NPC B ещё жив, и
`CCharacterPhysicsSupport::m_physx_ragdoll` указывает на wrapper; удаление в
reconcile давало use-after-free при последующем `ReleasePhysXRagdoll`.

**Модель ownership.**

- **game-owned:** `state->gameOwned == true`, NPC владеет wrapper;
- **detached quarantine:** `gameOwned == false`, owner отказался, wrapper можно
  удалить после reconciliation;
- **backend-destroyed:** `active == false`, `v2Handle == {}`,
  `kinematics == nullptr`, lease ref уже освобождён, wrapper может ещё жить у
  NPC.

**Изменения.**

- `OgsrPhysXRagdollState::gameOwned` (default `true`).
- `OgsrPhysXRagdollRelease`: при failed `RagdollDestroy` —
  `gameOwned=false`, `kinematics=nullptr`, quarantine.
- `ReleaseAllV2`: решение об удалении по `state->gameOwned`, а не по списку;
  game-owned wrapper сохраняется, handle/pose/callbacks инвалидируются.
- `ReconcileSceneDestroyV2`: для каждого quarantined state логирует wrapper,
  NPC, handle и ownership; освобождает один lease ref; `active=false`,
  `v2Handle={}`, `kinematics=nullptr`; удаляет только `!gameOwned`.
- `OgsrPhysXRagdollIsActive` + проверки в `Publish`/`ApplyBoneHit`/
  `ApplyCentralImpulse`: retired wrapper не публикует pose и не принимает
  impulses.
- `CCharacterPhysicsSupport::UpdatePhysXRagdoll` пропускает retired wrapper.

**Реальный порядок OGSR.** `CLevel::net_Stop`:
`OgsrPhysXRuntimeOnLevelUnload()` → `remove_objects()` → NPC destructor →
`CCharacterPhysicsSupport::ReleasePhysXRagdoll()` → `OgsrPhysXRagdollRelease`.
Поэтому wrapper B обязан пережить `SceneDestroy`.

**Fault-прогон (final binary).** `-physx_ragdoll_visual_replace
-physx_multi_instances -physx_ragdoll_reload`, persistent
`OGSR_PHYSX2_FAULT_RAGDOLL_DESTROY=1`:

```

## 1. Gate A — SDK lifetime

### 1.1 Что выяснено про PhysX 5.6.1

PhysX 5.6.1 допускает **только один `PxFoundation` на процесс**:
`FdFoundation.cpp` возвращает `invalid operation: Foundation object exists
already` при второй попытке. Legacy v1 world и v2 backend создают собственные
`PxFoundation`/`PxPhysics`, поэтому их **одновременное** существование
принципиально невозможно, независимо от extensions refcount.

`PxInitExtensions`/`PxCloseExtensions` — process-global singleton, привязанный
к первому `PxPhysics`. Делить его между двумя разными `PxPhysics` нельзя
доказуемо безопасно.

### 1.2 Реализованное решение: fail-closed exclusive lease

`include/physics_physx/physx_extension_lifetime.h` +
`src/physx_extension_lifetime.cpp`:

- один owner за раз: `LegacyV1` или `MultiV2`;
- re-entrant для того же owner (refcount);
- `PxInitExtensions` вызывается один раз при первом acquire;
- `PxCloseExtensions` — один раз при последнем release;
- acquire другого owner возвращает `false` с диагностикой
  `PhysX extensions are already owned by the ... runtime; simultaneous v1/v2
  use is not supported`;
- partial init failure не меняет refcount;
- release не уходит ниже нуля, double release игнорируется.

v1 `PhysXRagdollWorld` и v2 `PhysXContext` используют этот lease
(`LegacyV1` / `MultiV2`). Дополнительно `V2ModuleLease` получил
resource guard: `addResourceRef()` / `releaseResourceRef()`; `unload()`
отказывается вызывать `FreeLibrary`, пока живы scene/instances.

### 1.3 Поведение

| Сценарий | Результат |
|---|---|
| v1 alone → destroy | PASS |
| v2 alone → destroy | PASS |
| v1 alive → v2 create | **fail-closed** (`PxCreateFoundation`/lease), handle не публикуется |
| v2 alive → v1 create | **fail-closed**, handle не публикуется |
| v1 destroy → v2 create | PASS |
| v2 destroy → v1 create | PASS |
| partial v2 config failure | lease не отравлен, v1/v2 создаются после |
| repeated alternating loads (5×) | PASS |
| double v2 scene destroy | второй вызов отклонён |
| unload с активной scene | отклонён (`active resource(s)`), после destroy — PASS |

Тесты: `physics_physx_extension_lifetime_tests` **29 checks / 0 failures**,
`physics_physx_v2_lifetime_tests` **44 checks / 0 failures**.

**Вывод Gate A:** coexistence v1/v2 **не заявлен**. Реализован и доказан
fail-closed: одновременно активен только один backend; неподдерживаемый NPC
уходит в ODE. Игровой режим выбирает **либо** v1, **либо** v2, никогда оба.

## 2. Gate B/C — runtime и симуляция

### 2.1 Mode selection

| Флаги | Путь |
|---|---|
| без `-physx_ragdoll` | feature-off ODE |
| `-physx_ragdoll <target>` | P2.2A v1 |
| `-physx_ragdoll <target> -physx_multi_instances` | **v2 multi (2 NPC)** |
| `-physx_ragdoll_multi` | старый диагностический smoke |
| `-physx_ragdoll_multi` + `-physx_multi_instances` | **конфликт**: v2 отключён с логом |

ABI negotiation выполняется через `V2ModuleLease::negotiate()`:
`GetApiInfo` + exact exports + `OGSR_PHYSX2_CAP_REQUIRED_P3_1` + layout.
При отказе v2 не вызывается, NPC остаётся на ODE/v1 (в v2-режиме — ODE).

### 2.2 Level-owned scene

- Одна `OgsrPhysX2SceneHandle` на игровую сессию; создаётся **лениво при первой
  v2-активации**, чтобы static fragment был центрирован на области действия.
- Не создаётся на смерть каждого NPC; не уничтожается при `RagdollDestroy`.
- `SceneDestroy` — в `OgsrPhysXRuntimeOnLevelUnload()` после teardown NPC.
- `maxInstances = 2`; лимит применяется к живым instances, не к числу смертей.
- Static geometry: один fragment 48×24×48 м, cap 8192 треугольника, через
  существующий `Level().ObjectSpace.BoxQuery`; `static_tris=5258` в игровом
  прогоне. Runtime eviction нет; cooking failure уничтожает только новую сцену.

### 2.3 Один SceneStep

`CLevel::OnFrame()` вызывает `OgsrPhysXRuntimeOnFrame()` **до**
`Objects.Update/CalculateBones`. В v2-режиме:

1. `OgsrPhysXRagdollSmokeTick()` (игровые события/смерти);
2. один `OgsrPhysX2SceneStep(scene, Device.fTimeDelta, ++frameId, ...)`;
3. `simulate` + `fetchResults` внутри DLL;
4. затем `Objects.Update` публикует позы через bone callbacks.

Fixed dt 0.01, gravity −19.62, solver 16/4, damping 0.05/0.2. Pause/time
factor: при `Device.Paused()` или `delta <= 0` шаг не вызывается; frameId
после reload начинается с 0 (новая scene). Dropped steps логируются.

Игровой лог (2 NPC, одна scene):

```
ph_runtime: multi-instance v2 mode requested (max 2 live ragdolls)
ph_runtime: v2 scene created scene=(0,1) caps=0x0000007f max_instances=2 static_tris=5258
ph_ragdoll_v2: instance created scene=(0,1) instance=(0,1) live=1
ph_ragdoll_smoke: multi second hit id=12804 physx_instance=0 v2_live=1 step=111
ph_ragdoll_v2: instance created scene=(0,1) instance=(1,2) live=2
ph_runtime: v2 frame=600 step=557 live=2 scene=(0,1)
ph_runtime: v2 frame=720 step=669 live=2 scene=(0,1)
ph_ragdoll_smoke: multi destroying first PhysX NPC id=6525
ph_ragdoll_v2: instance destroyed instance=(0,1) live=1
ph_runtime: v2 frame=840 step=787 live=1 scene=(0,1)
ph_ragdoll_smoke: multi third hit id=12805 physx_instance_before=0 v2_live_before=1
ph_ragdoll_v2: instance created scene=(0,1) instance=(0,3) live=2
ph_ragdoll_smoke: multi result ... v2_live=2 step=890
ph_ragdoll_smoke: v2 B result handle=(0,1,1,2) publish=830 callbacks=39151
ph_ragdoll_smoke: v2 C result handle=(0,1,0,3) publish=60 callbacks=2867
ph_ragdoll_v2: instance destroyed instance=(0,3) live=1
ph_runtime: v2 frame=8400 step=7910 live=1 scene=(0,1)
```

**600 physics steps:** B активирован на step 111; условие destroy —
`stepIndex >= 111 + 600 = 711`. A уничтожен между логами step 669 и 787,
т.е. после 711. B продолжал публиковаться до step 7910 после удаления A.

### 2.4 Independent pose publication

- Каждый NPC хранит собственный `OgsrPhysXRagdollState` с `v2Handle`,
  `ownerId`, bone slots и `boneModel`.
- `Publish` читает только `RagdollGetPose(handle)` этого NPC.
- Bone callbacks устанавливаются на `IKinematics` конкретного NPC; при
  удалении A снимаются только его callbacks.
- B publish=830, callbacks=39151 после удаления A; C publish=60,
  callbacks=2867. Перекрёстных callbacks/общих pose buffers нет.

| Сценарий | Лог/результат |

поэтому нет dangling `m_physx_ragdoll`.

## 7. Известные ограничения и P3.2

1. **Один backend за раз.** v1/v2 coexistence запрещён PhysX (один
   `PxFoundation`); fail-closed lease это фиксирует. P3.2 может заменить v1
   world на общий SDK-контекст, если coexistence действительно нужен.
2. **Лимит 2 NPC** — per-scene `maxInstances`; третий NPC уходит в ODE.
3. **Ленивое создание scene** на первой активации (для центра static fragment)
   вместо `OnLevelStart`; одна scene на сессию, не на NPC.
4. **Static fragment 48×24×48 м / 8192 треугольника.** NPC вне области не
   получат collision; для больших уровней нужен fragment manager/streaming.
5. **Один поток-владелец.** Registry/backend без mutex; SceneStep не
   реентерабелен.
6. **SceneDestroy требует снятия bone callbacks** — реализовано через
   `ReleaseAllV2`; при неудачном `RagdollDestroy` состояние уходит в quarantine
   и повторяется на shutdown, сцена и DLL lease не освобождаются.
7. **Feature-off full build** проверен; Debug PhysX — среда.
8. **Fault injection** — только env-переменные
   `OGSR_PHYSX2_FAULT_RAGDOLL_DESTROY` / `OGSR_PHYSX2_FAULT_SCENE_DESTROY`;
   в production их нет.
9. **P3.2 prerequisites:** per-area static fragments, capacity policy,
   save/load, network, player ragdoll, stress >2.
