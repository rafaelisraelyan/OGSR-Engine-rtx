# F4.0-B-VSLICE

Экспериментальный игровой DX12 viewport показывает ограниченный статический сектор 129 уровня Jupiter. Сцену составляют пять декодированных геометрических источников и их размещения из ресурсов игры. Пятнадцать кандидатов с неподдержанным форматом отражаются в диагностике. Путь R4 остаётся режимом обычного запуска.

## Сборка и запуск

Соберите `Engine.sln` в Release x64 с `OGSR_ENABLE_EXPERIMENTAL_DX12_GAME_BRIDGE=true`. Для записи кадров и диагностической камеры включите также `OGSR_ENABLE_EXPERIMENTAL_DX12_GAME_CAMERA_CAPTURE=true`. Оба свойства по умолчанию выключены.

Запуск игры с существующим сохранением Jupiter, доступным через текущий `fsgame.ltx`.

```powershell
.\xrEngine.exe -dx12_native_game -nogameintro -log -start 'server(b23_jupiter/single/alife/load)'
```

`-dx12_game_bridge` включает прежний диагностический режим с R4 swapchain. При наличии обоих флагов остаётся этот диагностический режим. Для `-dx12_native_game` требуется аргумент `-start server(...)`. Если создание native viewport завершается ошибкой, лог указывает причину. R4 можно выбрать при следующем запуске без native-флага.

## Геометрия и материалы

- VFS передаёт снимок ресурсов активного уровня. M1 разбирает сектора, hierarchy и диапазоны исходных VB/IB, проверяет session и epoch, затем передаёт геометрию в ограниченный GPU registry. Ресурсы загружаются при активации Jupiter и живут до смены уровня или подтверждённого окончания использования.
- Материалы связывают поддержанный visual с R4 shader ID, первым DDS и THM. Проверенный набор использует BC1 sRGB, декодированные UV и геометрические нормали. Остальные visual и форматы отмечаются в диагностике. Доступны textured, material ID, UV/normal и unsupported mask captures.
- Путь рассчитан на статический набор Jupiter. Покрытие уровня, динамические объекты, HUD, игровой DX12 вывод других карт и полный набор эффектов R4 выходят за границы этого среза. Игровая логика и её ресурсы по-прежнему обслуживаются существующим движком.

## Native frame и GR

- В native mode игровой HWND принадлежит DX12 swapchain. Существующий D3D11 device обслуживает совместимость игровых ресурсов. Два слота DX12 владеют backbuffers, allocators и command lists. Слот ждёт собственный fence перед Reset. Перестройка depth и backbuffers требует подтверждения завершения очереди. При неизвестном состоянии GPU связанные COM-ресурсы остаются в quarantine.
- Игровой view-projection поступает из движка. Текущий размер клиента используется для viewport и коррекции aspect. Изменение размера не требует повторного чтения `level.geom`. Level reload и `vid_restart` проверяют epoch перед использованием registry.
- `OGSR_DX12_GAME_GR=serial|parallel|verify` выбирает режим подготовки. GR использует общий пул J2A и неизменяемый снимок сцены. Verify сравнивает порядок и данные serial и parallel packets. Подготовка публикует результат после завершения задач. GPU запись и submission остаются последовательными.
- `OGSR_DX12_GAME_METRICS=1` пишет cadence, CPU preparation и recording, fence, слот и параметры камеры. `gpu_present` указывает исходный успешно показанный кадр для отложенного `gpu_ms`. Нулевой `gpu_present` пропускается при расчёте GPU-выборки.

## Запись доказательств

Для camera-on задайте `OGSR_DX12_NATIVE_CAPTURE_DIR` как существующую локальную папку и включите `OGSR_DX12_GAME_METRICS=1`. В `user_ogsr.ltx` задайте `vid_mode 1280x720` до запуска. При размере viewport до 1920×1080 захватываются 30 последовательных scene presents начиная со 120-го кадра с draws. Если клиентская область больше лимита в момент начала захвата, движок отменяет запись для текущего запуска.

GPU копирует кадры в один readback. После подтверждения fence движок один раз сохраняет `native-frames.rgba`. Лог `ph_dx12_capture` связывает снимки с номерами Present, слотами и fences, а метрики добавляют положение и направление камеры. Размер, pitch и stride находятся в итоговой записи `ph_dx12_capture`. Выключенный режим не копирует backbuffer в readback.

Отчёт `F4.0-B-VSLICE-Implementation-Report.md` и архив `OGSR-F4.0-B-VSLICE-Delivery.zip` документируют проверенный SHA, результаты, артефакты и открытые критерии.
