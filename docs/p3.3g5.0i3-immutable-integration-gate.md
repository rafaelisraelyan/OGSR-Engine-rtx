## 2. Close F2 without changing F1 ownership semantics

The R2 source introduced `m_bDestroyed` guards for `Destroy()` and `StopForced()`. Independent review found that the ordinary `CUISequencer::Stop()` does **not** guard `m_bDestroyed` before pause-state handling.

Make the **smallest targeted correction** (or provide a code- and runtime-backed invariant proving repeat `Stop()` cannot be invoked). Verify:
- `Stop()` after a prior `Destroy()` does not perform a second pause/input/device mutation, if re-entry is a supported call sequence; never invoke a method on an object already deleted.
- `StopForced()` repeated before owner deletion leaves `seqFrame=0, seqRender=0`, no extra `IR_Release`, no Lua stop callback, no recreated intro, and exactly one owner delete.
- normal `Stop()` still runs sequencer- and item-level Lua side effects exactly as intended, including `etsPlayEachItem → Next()` path; no accidental loss of normal intro UI behavior.
- `intro_logo`, `game_loaded`, `intro_game` paths, including active `intro_game` forced teardown with `g_actor == nil`.
- deferred `m_dialogsToRender_new`: add during `OnFrame`, remove/cancel during update, delete, flush, no stale pointers.

Produce a **separate F2 patch and deterministic regression**, preserving prior 48/48 reference checks and reporting any newly added assertions explicitly. Do not introduce new PhysX features.
