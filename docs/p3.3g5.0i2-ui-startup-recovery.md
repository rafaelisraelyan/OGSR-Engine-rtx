# P3.3-G5.0-I2 — Baseline UI Startup Crash: Root Cause, Fix & Regression Gate

> **Статус:** TASK DEFINED / IMPLEMENTATION NOT STARTED / G5.0 MERGE HOLD.
> **Дата:** 2026-11-06. **База:** актуальный `origin/prypiat` на момент исполнения, не зафиксированная историческая SHA.
> **Цель:** расследовать и минимально исправить общий startup-crash в главном меню OGSR, затем проверить PhysX integration без diagnostic workaround.
> **Граница:** это baseline/UI defect track. Никаких новых PhysX, DX12 или ODE features. G5.1 НЕ начинать.

## 0. Обязательные источники и подтвержденные факты

Прочитать `AGENTS.md`, `docs/08-roadmap.md`, `docs/p3.3g5.0i1-independent-review.md`, `docs/physics-portability-adr.md` и **реальные исходники актуального HEAD**.

Прошлый независимый G5.0-I1 review: `SOURCE INTEGRATION — CONDITIONAL PASS / MERGE HOLD`. Обычный startup без `OgsrDiagnosticRuntimeWorkaround` падает с `0xC0000005`, стек: `CDialogHolder::OnFrame` → `CMainMenu::OnFrame`; проблема воспроизводится как в чистом `origin/prypiat` feature-off baseline, так и в PhysX integration. Пять minidumps подтвердили код исключения и точку, но **не доказали причину и тождественность механизма повреждения**. Diagnostic workaround позволял пройти архивный smoke; он не является production fix.

Текущие source investigation anchors (путь и актуальную строку перепроверить в своём checkout):
- `ogsr_engine/xrGame/UIDialogHolder.cpp` — `CDialogHolder::OnFrame`, `TopInputReceiver`, `SetMainInputReceiver`, `CleanInternals`, `m_input_receivers`, `m_dialogsToRender`, `m_dialogsToRender_new`;
- `ogsr_engine/xrGame/UIDialogHolder.h` — raw pointer ownership/storage;
- `ogsr_engine/xrGame/MainMenu.cpp` — `CMainMenu::OnFrame`, `ReloadUI`, `Activate`, `DestroyInternal`, `m_startDialog`, `IR_Capture`/`IR_Release`;
- `ogsr_engine/xrGame/ui/UIDialogWnd.cpp` — `ShowDialog`, `HideDialog` and holder transfer.

В текущем исходнике `CDialogHolder::OnFrame` вызывает `wnd->Update()` после `TopInputReceiver()`, а `CMainMenu::ReloadUI` вызывает `HideDialog`/`CleanInternals` перед заменой `m_startDialog`. Эти места **подозреваемые для проверки**, а не установленная root cause.

## 1. Baseline isolation — прежде чем писать fix

1. В исходном Windows workspace сохранить `git status --short`, `git branch -avv`, `git rev-parse HEAD`, `git remote -v`, `git ls-remote origin refs/heads/prypiat`; зафиксировать SHA, build IDs, SDK, assets/save hashes, конфигурацию GPU/renderer, UI mods и launch arguments.
2. В отдельном чистом worktree от **актуального `origin/prypiat`** создать ветку `fix/g50i2-ui-startup-baseline`. Не работать поверх PhysX experiment. Не делать reset/clean/rebase в существующем пользовательском worktree.
3. Собрать baseline **обычный Release x64 без PhysX и без `OgsrDiagnosticRuntimeWorkaround`**; символы/PDB должны соответствовать бинарнику и source commit. Сохранить точный build command, environment и SHA-256 EXE/DLL/PDB.
4. Воспроизвести падение на одинаковом контенте/save/settings. Выполнить серию холодных запусков (целевой минимум 5) со сценариями main-menu/new game и loading existing save; записать run IDs, результаты, журналы, dumps. Не объявлять причину от имени PhysX только по совпадению стека.

## 2. Debug root cause, do not mask symptoms

Для каждого релевантного dump с корректным PDB: exception record/`!analyze -v`, address, instruction, faulting thread, call stack, receiver state, relevant raw pointers/owners and frame sequence. Сравнить baseline ↔ integration при совпадающих бинарных версиях/asset conditions.

Добавить временную **диагностику (в отдельный debug instrumentation patch)** событий:
- creation/destruction main menu and `CUIDialogWnd`;
- registration/removal/top input receiver, owner/holder transitions;
- dialog render queues including pending `m_dialogsToRender_new`;
- `ReloadUI`, `Activate`, `HideDialog`, `StopMenu`, `CleanInternals`;
- `Device.seqFrame` and event-order at load/unload;
- `wnd`, `this`, `m_startDialog` identity (не обращаться к уничтоженным объектам ради логов).

Различить: dangling pointer / UAF, invalid vector state, double update/reentrancy, dialog destruction ordering, UI asset incompatibility, or another evidenced cause. Не делать вывод о UAF или битой модели по одной строке `wnd->Update()`. Проверить, участвует ли `m_dialogsToRender_new` в dangling references после `CleanInternals`; подтвердить или отклонить фактами.

**Неприемлемые «исправления»:** `try/catch` вокруг crash, скрытое игнорирование исключений, принудительная пауза/timeout, отключение обычного меню, production `OgsrDiagnosticRuntimeWorkaround=true`, бездоказательное `if(wnd)` как единственная защита (проверка уже есть).

## 3. Minimal baseline-only fix

После установления причины внести **самый узкий корректный** production patch в UI/main-menu lifecycle на ветке baseline fix. Для каждого изменённого метода: доказать owner/lifetime invariant до/после и показать тест на старом коде (FAIL) → на исправленном (PASS), если возможно воспроизвести детерминированно.

- Не трогать `PhysicsPortable`, `PhysicsPhysX`, `PhysicsAdapterOGSR`, `xrPhysics` или existing DX12 renderer.
- Не менять `Engine.sln`, `XR_3DA.vcxproj`, `OgsrBuildProps.props`, compile flags/initialization для обхода.
- Не чинить UI через отключение main-menu, ввод специальных archive launch arguments, изменение game assets без доказательств.
- Отдельно проверить lifecycle при многократном `ReloadUI`, open/close Main Menu, save load, exit, level reload, смене aspect ratio (если используемый код это делает).

## 4. Baseline acceptance

После fix: чистый Release x64, feature-off, no workaround; на **пяти холодных запусках** с одинаковой репродукцией **0 новых UI exceptions**, успешный normal menu, new game, save-load, минимум два reload; любые flaky/reproducible crashes — FAIL с сырым evidence. Regression script/unit harness для UI lifecycle если возможен. Check `git diff --check`, PDB/build hash и отсутствие unintended changes.

Если причину нельзя доказать или чистый baseline не проходит — `BLOCKED: BASELINE UI ROOT CAUSE / NORMAL STARTUP`; продолжение интеграции и G5.1 запрещены.
