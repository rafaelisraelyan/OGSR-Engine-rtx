## Реализация

GR Job System остаётся отдельным Engine Core module. Его код и enkiTS на этом
этапе не менялись. Единственный потребитель — standalone `xrDX12Smoke`.
JobSystem — локальный объект WinMain, один на жизненный цикл приложения.
Пул запускается один раз, если нужен Parallel или проверка Serial/Parallel.
Чистый Serial и исходный двухкубовый режим не запускают рабочие потоки.
Покадровые JobGroup не создают новый pool. В лог пишутся фактические workers,
число запусков, submitted/completed, ошибки и нулевое число участников после Shutdown.

CPU-сцена opt-in через `-stress N`: независимые S*R*T world transforms и
консервативное отсечение сфер шестью плоскостями frustum. Эти CPU-объекты
не добавляют GPU draw calls: исходные два куба продолжают рисоваться прежним
путём. Command lists не записываются параллельно. DX11, основной рендерер,
физика, AI, анимация и аудио не изменялись.

Исправлены дефекты уже имевшейся незавершённой реализации:

- Извлечение frustum из столбцов row-vector матрицы DirectXMath; near-plane
  соответствует D3D `0 <= z <= w`, нормали направлены внутрь.
- `-jobs serial -jobsverify` действительно вычисляет Parallel для сравнения.
- Отказ запуска пула не маскируется проверкой Serial/Serial.
- 30 кадров прогрева исключены из статистики; `-cputest N` измеряет ровно N кадров.
  Прежний exe для N=5 выдавал 36 verifyFrames.
- Время обоих путей включает одинаковый подсчёт checksum/visibility. Parallel
  включает создание/освобождение группы, отправку, Wait и reduction.
- Хеширование матриц через memcpy вместо нарушения strict aliasing.
- CompareStates отвергает NaN/Inf и считает расходящиеся объекты, а не компоненты.
- Аспект CPU-сцены обновляется при обычном и интерактивном resize.

Изменены `xrDX12Smoke.cpp`, `xrDX12Smoke.vcxproj`, `dx12cpuscene.cpp/.h`.
Добавлены `dx12cpuruntime.inl`, `dx12cpuscene_tests.cpp`,
`tests/run-cpu-runtime.ps1` внутри `ogsr_engine/Layers/xrRenderDX12` и этот отчёт.
Файлы CHW12, dx12mesh, dx12camera, GPU synchronization и проект xrRender_R5_DX12
побайтово совпадают со снимком начала этапа.

## Сборка и runtime

ReleaseDX12|x64, v143, C++20, /MT, /EHsc: сборка цели xrDX12Smoke через
Engine.sln прошла с 0 ошибками и 0 предупреждениями. Полная сборка игровых
целей не выполнялась. Информационное сообщение о повторной линковке /LTCG
от существующей DX12-библиотеки не является предупреждением.

32 автоматических запуска завершились кодом 0:

- CPU-самотест: 857 проверок, 0 ошибок. Размеры 256/1024/4096/16384,
  workers 0/1/2/4/8, grain 1/64/65536, три времени и два aspect ratio.
- Depth readback без CPU-нагрузки и с Parallel: три ожидаемых пикселя прошли
  проверку (ближний куб, дальний куб, фон), затем GPU drained before shutdown.
- Автоматический resize при Parallel: 1280×720 → 960×540 → 1280×720,
  пересоздание D32 depth buffer, 60 измеряемых кадров, mismatches=0.
- 16 сочетаний четырёх размеров сцены и 1/2/4/8 workers: по 200 измеряемых
  кадров после 30 прогревочных, Serial/Parallel checksum, visibility и матрицы совпали.
- Четыре Serial-прогона с реальной Parallel-проверкой: по 30 кадров.
- Восемь отдельных benchmark-прогонов: Serial и Parallel для каждого размера,
  по 200 кадров, без вычисления второго пути.

Аппаратный D3D12 device: NVIDIA GeForce RTX 5070 Laptop GPU. Debug layer и
GPU-based validation включены; warning/error/corruption сообщений нет.
Логи подтверждают исходную геометрию 72 vertices / 2 cubes и завершение GPU.
Топология, сообщённая GR: 12 физических ядер, 24 логических процессора.
Автоматическая политика выбирает 6 workers; сравнительные числа ниже — при 4.

Отдельный CPU-самотест с AddressSanitizer также прошёл 857 проверок без ошибок
памяти. Повторно выполнены обычные регрессии GR: 31 тест / 388 проверок / 0 ошибок.

Визуальная проверка окна инструментами этой сессии недоступна. PASS относится
к реальному запуску, readback, логам и кодам выхода; не к визуальному осмотру.
Интерактивный drag-resize/minimize/restore вручную не проверялся. Во время
модального drag-resize сохранён прежний WM_TIMER GPU-путь; CPU-этап выполняется
в обычном основном цикле, а не в реентерабельном оконном callback.

## Корректность и границы проверки гонок

Входная таблица объектов неизменяема; снимок камеры локален кадру, передаётся
в задачи только для чтения и живёт до Wait. Worker пишет лишь свой диапазон
ObjectState, без push_back/resize и без чтения CHW12. Reduction выполняется
главным потоком после Wait; следующий кадр не переиспользует незавершённые данные.

Самотест использует отдельные атомарные счётчики записей: каждый индекс должен
иметь ровно одного writer. Повторная запись фиксируется и не выполняется, чтобы
сам диагностический режим не создавал гонку. Проверяются защитные элементы
выхода и неизменность входа. Независимый oracle сравнивает culling точек с
неравенствами clip-space, поэтому одинаковая математическая ошибка двух путей
не может скрыться только за Serial/Parallel совпадением.

Эти проверки и схема владения дают основание для отсутствия конфликтующих
доступов в данном этапе. ThreadSanitizer не запускался; ASan не является race
detector и не доказывает отсутствие всех возможных гонок. Сохраняются ограничения
GR из README, включая неподдерживаемое восстановление частичного запуска enkiTS.

## CPU-время

Одна локальная серия, 4 workers + вызывающий поток, grain=64, 30 прогревочных
и 200 измеряемых кадров. Оба пути получают один снимок; порядок запуска
Serial/Parallel чередуется. Время сцены в автотестах — номер шага / 60,
поэтому входы воспроизводимы между запусками. Время GPU-кадра сюда не входит.

Средние значения в миллисекундах, формат: Serial total / Parallel total;
submit; wait-helping; reduction; пустое задание:

- 256 объектов: **0.024141 / 0.037532**; 0.011288; 0.024020; 0.001268; 0.010482.
- 1024 объекта: **0.114042 / 0.059029**; 0.012619; 0.040774; 0.004590; 0.012079.
- 4096 объектов: **0.383540 / 0.136484**; 0.012383; 0.107105; 0.015975; 0.012414.
- 16384 объекта: **1.301304 / 0.421946**; 0.010019; 0.357892; 0.053046; 0.011783.

p95 Serial / Parallel: 0.0377/0.0583, 0.1519/0.0798, 0.5896/0.1828,
1.7696/0.5647 ms соответственно. Все p50/p95/p99 и исходные покадровые
измерения сохранены в логах; перцентили берут нижний индекс p*(N−1).

Отдельные прогоны без сравнения дали средние Serial / Parallel:
0.024469/0.037817, 0.099530/0.063926, 0.381864/0.139969,
1.227182/0.474593 ms соответственно.

Wait включает полезную работу вызывающего потока, это не чистый простой.
Submit также потенциально может выполнять задачи. Empty-dispatch — отдельное
пустое задание с тем же разбиением, приближённая оценка scheduler overhead;
она не вычитается из total. Разница total и submit+wait+reduce включает владение
группой и измерительную обвязку. Построение снимка камеры, сравнение результатов,
пустое задание и запись логов исключены из total обоих путей. Raw samples
пишутся после завершения измерений. Пустое задание выполняется только в автопрогонах.

В этой серии Parallel проигрывает на 256 объектах и выигрывает на больших
CPU-сценах. Это не прирост FPS и не оценка производительности игрового рендерера.
Результаты одной серии на ноутбуке не устанавливают универсальный порог выбора
режима: частоты, нагрузка ОС и прогрев влияют на время. Serial остаётся default.

## Воспроизведение

Из корня репозитория, сборка в Developer Command Prompt:

```bat
MSBuild.exe Engine.sln /t:xrDX12Smoke:Rebuild /p:Configuration=ReleaseDX12 /p:Platform=x64 /m:1 /nr:false
```

Автоматическая матрица из PowerShell:

```powershell
& .\ogsr_engine\Layers\xrRenderDX12\tests\run-cpu-runtime.ps1 -Frames 200
```

Логи и JSON с метриками: `x64/f32c2/*.log`, `x64/f32c2/runtime-results.json`
(локальные игнорируемые артефакты). Скрипт ограничивает каждый запуск 45 секундами.

Точные команды отдельных проверок и ручного окна:

```powershell
& .\x64\ReleaseDX12\xrDX12Smoke.exe -cpuselftest
& .\x64\ReleaseDX12\xrDX12Smoke.exe -depthtest
& .\x64\ReleaseDX12\xrDX12Smoke.exe -jobs parallel -stress 4096 -jobworkers 4 -cputest 200 -resizetest
& .\x64\ReleaseDX12\xrDX12Smoke.exe -jobs serial -stress 4096 -cpubench 200
& .\x64\ReleaseDX12\xrDX12Smoke.exe -jobs parallel -stress 4096 -jobworkers 4 -cpubench 200
# Окно без автозакрытия: осмотреть два куба, resize, minimize/restore, закрыть крестиком.
& .\x64\ReleaseDX12\xrDX12Smoke.exe -jobs parallel -stress 4096 -jobworkers 4 -jobsverify -freeaspect
```

`-jobs gr` сохранён как alias `parallel`; `-jobworkers 0` означает автоматический
выбор, а не нулевое число workers. Последовательный пользовательский путь —
`-jobs serial`. `-cputest` всегда сравнивает оба пути; `-cpubench` — только выбранный,
если дополнительно не указан `-jobsverify`.

F3.2C.2 завершён в пределах этих проверок. Следующий этап требует ревью;
дальнейшая интеграция и параллельная запись D3D12 command lists не выполнялись.
