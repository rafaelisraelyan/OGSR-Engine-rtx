## Контракт сессии

Каждая из трёх сессий должна содержать ровно такую последовательность
ключевых событий:

```text
tick frame=1
-> lethal hit (PhysX target)
-> PhysX ragdoll created bodies=11 joints=10 bones=47
-> owner committed to PhysX
-> multi spawned two extra stalkers
-> multi second hit ... physx_instance=1
-> multi destroying first PhysX NPC
-> releasing PhysX owner state + PhysX ragdoll instance released
-> multi third hit ... physx_instance_before=0
-> PhysX ragdoll created bodies=11 joints=10 bones=47
-> owner committed to PhysX
-> multi result second=1 shell=1 third=1 shell=0 physx_instance=1
-> reload gate requesting level disconnect
-> [сессии 1 и 2] ragdoll reload N/2 + owner release + reloading level
```

## Проверки

| ID | Что проверяется |
|---|---|
| `sessions.count` | ровно 3 сессии |
| `session.N.sequence` | точный порядок ключевых событий сессии |
| `creation.count` | ровно 6 созданий PhysX ragdoll |
| `creation.geometry` | каждое создание `bodies=11 joints=10 bones=47` |
| `creation.mass` | `total_mass=92.21`, `root_mass=9.88` |
| `ownership.commits` / `ownership.releases` | 6 commit и 6 release |
| `ownership.balance` | commit/release чередуются, имя release совпадает с owner |
| `instance.released` | ровно 3 освобождения instance |
| `session.N.ids` | first/second/third id различаются, destroy == first |
| `session.N.second.ode` | второй NPC получает ODE fallback (`physx_instance=1`) |
| `session.N.third.reuse` | третий NPC стартует без instance (`physx_instance_before=0`) |
| `session.N.result` | `second=1 shell=1 third=1 shell=0 physx_instance=1` |
| `reload.sequence` / `reload.levels` | reload `[1, 2]`, два `reloading level` |
| `reload.cap` | нет `3/2` и номеров больше 2 |
| `reset.tick1` | ровно 3 `tick frame=1` (сброс состояния на каждом уровне) |
| `timestamp.monotonic` | ключевые события не идут назад по времени |
| `crash.markers` | нет `Unhandled exception`, `ScriptCrashHandler`, stack trace, FATAL, assertion, ACCESS_VIOLATION |

## Fault injection

Harness создаёт восемь копий принятого лога и требует FAIL с конкретным ID:

| # | Повреждение | Ожидаемый FAIL | Exit |
|---|---|---|---:|
| 1 | удалён `multi result` третьей сессии | `session.3.sequence` | 1 |
| 2 | `second shell=1` заменён на `shell=0` | `session.2.result` | 1 |
| 3 | `physx_instance_before=0` заменён на `1` | `session.1.third.reuse` | 1 |
| 4 | удалён owner release третьей сессии | `ownership.balance` | 1 |
| 5 | добавлен `ragdoll reload 3/2` | `reload.cap` | 1 |
| 6 | `bodies=11 joints=10` заменено на `10/9` | `creation.geometry` | 1 |
| 7 | добавлен `Unhandled exception` | `crash.markers` | 1 |
| 8 | удалён `tick frame=1` третьей сессии | `reset.tick1` | 1 |

## Ограничение

Это log-level строгий валидатор. C++-рефакторинг smoke-сессии в
`ogsr_physx_smoke_session.h` + `test_physx_smoke_session.cpp`, который,
вероятно, входил в отсутствующий патч, не выполнялся: он меняет исполняемый
код и потребовал бы новой сборки и повторного runtime-прогона. Текущий
валидатор проверяет тот же контракт по полному runtime-логу.
