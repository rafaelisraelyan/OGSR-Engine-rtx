### P0-B1 implementation

GameDx12AdaptiveShadowPlan.h provides a dynamic logical admission/resolution policy. It accepts caller-supplied power-of-two resolution tiers and per-face accounted costs (not actual DXGI reservations), precomputed importance and requested resolution, budget, session/epoch/frame/policy identity. No fixed candidate count or bank/type ratio. Complete spot (one face) and point (six faces) groups; stable ID tie-break; previous admitted resolution/type drives bucket hysteresis and 1.25 retention priority, invalidated by identity/quality change. In two passes, admit minimum-resolution groups by priority, then upgrade admitted groups by priority within the remaining budget. This deliberately favors broader shadow coverage over maximum resolution for one source; it is not a globally optimal packing algorithm. Budget-denied lights are returned explicitly with resolution/bytes zero; no change to their lighting contribution yet. Invalid/duplicate input fails without replacing the prior output. Allocation exceptions propagate to owner. No GPU objects, actual physical page/slice placement, frame-time enforcement, or live admission/GR path changed.

### P0-B2a: frame-slot shadow page placement (CPU implemented)

GameDx12ShadowPagePlan.h maps the existing logical AdaptivePlan to resolution-specific Texture2DArray page IDs and contiguous layer ranges. A page has an owner-supplied actual resource cost, resolution and layer count; spot groups take one layer and point groups six contiguous layers of the same page. There is no fixed count of pages or lights. Page size is allocation granularity, not a global quota. Budget accounts for whole retained/new pages (including internal unused layers), not nominal bytes of occupied faces. Preserve compatible surviving ranges; fill compatible existing pages, reuse empty compatible pages, and create more only when budget allows. Return explicit create/retire/physical-denial lists. Logical denials from B1 remain in its input plan. Physical placement is greedy, retention first, then point groups before spots, stable ID tie-break: it may deny a group because of fragmentation or whole-page cost and does not yet re-run admission/quality downgrade by priority. No claim of globally optimal packing or no starvation.

Chosen contract: one independent arena per fenced frame slot, not cross-frame sharing. Page IDs are slot-local; actual handles need slot + device epoch + page ID. Prior arena must match slot and its fence must have completed; reject UINT64_MAX completion (device removal sentinel), invalid/overlapping prior ranges, duplicates and stale same-identity frames. Epoch/policy changes retire old pages after completion. New state is provisional: owner reserves submit fence, applies retire/create, records and publishes only after successful queue signal; reconcile allocation failure or cancellation before reusing the logical state, quarantine unknown completion. No GPU depth content reuse or asynchronous destruction is implemented. Budget must be apportioned across slots and other allocations at the owner; this code is not a residency manager.

### P0-B2b: physical D3D12 shadow page owner (source implemented, GPU validation pending)

New header GameDx12ShadowPageResources.h owns real committed DEFAULT-heap depth arrays: R32_TYPELESS resource, D32_FLOAT per-layer CPU DSV and R32_FLOAT whole-array CPU SRV. One mip, single sample, optimized depth clear 1.0, initial PIXEL_SHADER_RESOURCE. API dimensions validated before querying/creating. Single-node D3D12 only; multi-node devices explicitly rejected rather than guessing node masks. QueryShadowPageSpec gets adapter-specific size from GetResourceAllocationInfo(0,1,&desc), rejects zero/UINT64_MAX size and zero alignment. Sizes are resource allocation costs, not exact measured resident usage (descriptor heaps and other allocations excluded).

QueryShadowMemoryBudget validates DXGI adapter LUID against device, queries node 0 LOCAL segment, computes saturating max(Budget-CurrentUsage-reserve,0). PrepareBudgeted refreshes this observation before staging. Owner supplies separate per-slot final page allowance and reserve for other pending allocations. No reservation or residency guarantee; the global allocator and across-slot budgeting remain to be integrated. Prepare accepts explicit additional headroom for deterministic fixtures. Whole-page costs enforce final page budget; staged new costs enforce separate incremental headroom (old resources stay alive during creation for rollback). Allocation failure publishes nothing, keeps current pages. This conservative strategy may reject a replacement that would fit after retiring old pages; retry with lower resolution or explicit safe retirement/replan at owner boundary. No forced memory eviction.

Lifetime: owner Initialize binds one slot to device/fence. Prepare queries real GetCompletedValue and refuses an in-flight prior slot; UINT64_MAX means device removal, never completion. Prepared view exposes only placed slices, borrowed resource and descriptor handles. Owner records transitions/clears, restores used subresources to PIXEL_SHADER_RESOURCE, copies SRVs into its fenced shader-visible heap, and submits via existing queue. Only after successful Signal of reserved fence call CommitSubmitted. Retired old pages are released then (prior slot already complete). CancelUnsubmitted is legal only when recorded lists are discarded without execution. Failed/ambiguous execution or signal requires terminal Quarantine, including caller's descriptor heaps/lists; deliberate process-lifetime retention rather than unsafe release. Release refuses outstanding work; destructor quarantines on failed Release. Same monotonic fence timeline and owner-thread ordering are mandatory caller contracts; no hidden wait/submit or cached depth validity. This module is not yet connected to GameDx12NativeFrame/Bridge/StaticScene; old banked runtime and shader ABI unchanged. No duplicate diagnostic resource allocation in game.

WARP fixture test-f43-shadow-page-resources-warp.cpp creates actual resources and copies SRVs to a shader-visible heap; clears two independent layers and checks full depth readback; holds queue behind a gate to verify in-flight reuse/release refusal, then tests retained physical page, rollback, replacement headroom and optional actual DXGI budget query (WARP may not report LOCAL budget). Debug Layer/GBV enabled and InfoQueue checked, allowing only intentional optimized-clear mismatch warning. It does not execute an SRV sampling shader or inject device removal. Added to existing Windows runner. This environment has no Windows SDK/MSVC/WARP or GPU execution; fixture is authored, NOT RUN. No new CPU test result is claimed for this Windows-specific revision. Next: owner integration with actual adapter/queue/fence and global budget coordinator; dynamic GPU metadata, shader-visible descriptor placement, per-view render scheduling, physical denial feedback; run native Windows build/WARP and real-world A/B before switching defaults.
