# Маршрут работы с кодом

Порядок действий при любом вопросе по кодовой базе. Отклоняться — только если
пользователь прямо попросил иначе.

## Шаги

1. **Точный путь известен** → открыть файл сразу. Не искать повторно то, что
   уже указано.
2. **Путь неизвестен** → искать внутри выбранной области (`ogsr_engine/`,
   `Game/`, `3rd_party/`) по:
   - символам и именам (`NVSDK_NGX_`, `CScriptEngine`, `rt_Position`)
   - тексту ошибки при ее наличии
   - терминам и макросам (`USE_ACES`, `SPAWN_VERSION`, `stdcpp20`)
   - импортам (`#include`, `#pragma comment(lib`)
   - конфигурации (`*.vcxproj`, `*.props`, `*.cmd`, `fsgame.ltx`)
   - тестам и их именам
3. **Открывать только совпавшие файлы.** Не читать соседей «для комплекта».
4. **Внутри файла:** найти нужную строку или символ, прочитать небольшой
   диапазон вокруг него и целиком связанную логическую единицу
   (функция, класс, build target, шаг инициализации).
5. **Расширяться** до imports, callers, dependencies и tests — только если
   после шага 4 не хватает контекста.

## Большие файлы и логи

Работать через размер → поиск → диапазон → `head` / `tail` / фильтры.
Не читать целиком файл, который можно сузить поиском.

## Что исключать по умолчанию

- секреты: `*.pem`, seed'ы, токены, `.env`
- `node_modules/`, `dist/`, `build/`, `bin_*/` (кроме случая, когда именно
  артефакт сборки — предмет задачи)
- кэши: `*.ipch`, `.shader_cache`, `shaders_cache/`
- generated и minified файлы
- большие логи (если лог не сам по себе разбирается)
- базы данных целиком
- временные массивы данных и посторонние медиа

### Исключение для этого репозитория

`3rd_party/` — это вендоренные зависимости, но именно там лежат SDK NVIDIA
DLSS (`NVIDIA_DLSS/`) и FidelityFX. Когда задача про них, туда идти нужно:
исключение «dependencies» применяется к движковому коду (`ogsr_engine/`),
а не к целям задачи.

## Инструменты поиска

- Основной: `rg <pattern> -g '*.cpp' -n`
- В этой среде `rg` может отсутствовать на PATH. Фолбэк — тул `grep`
  (regex + include-фильтр) либо `Select-String -Path/-Include -SimpleMatch`.
- Для точного текста — `-SimpleMatch`, иначе спецсимволы (`(`, `[`, `\`) съедаются
  как regex.
